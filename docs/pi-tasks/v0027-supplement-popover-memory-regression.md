# V0027面板内存增长专项补充
接续迁入任务，不重复主体。


## 用户新增重点：原 Calmon 点击菜单后内存持续增加
用户报告旧Calmon打开/点击菜单后内存开始增长。仅凭现象不能断言已定位泄漏，不直接继承来源的“已优化”结论。迁入时将其列为必验项。
- 审查popover/NSHostingController关闭释放或有界复用、Combine/Observation/通知token、事件monitor、Timer、Task、闭包捕获和图标缓存。排查每次点击新订阅/新采样、关闭后持续采样、view/model循环引用、重复NSStatusItem及缓存无界。
- 监控与日历分别测试：冷启动基线→首次打开预热→关闭静置→至少30轮打开关闭→关闭静置；另连续打开至少3分钟。记录同进程带时间戳RSS与physical footprint、采样在途/回调次数、缓存条目及可注入对象释放证据，区分首次系统/字体/图标缓存预热和持续阶梯增长。不能拿单次最高值或仅关闭回调数量宣称无泄漏，也不承诺关闭后RSS必须回到精确初值。
- 隔离fake事件/应用数据先验证结构；真实公开系统指标只读必要有界核对，不查个人日程/账号，不执行真实媒体控制。重复测试不要触碰用户正在运行的dist，隔离候选进程自行退出清理。
- 关闭弹窗后应用内存列表/磁盘/日程读取和面板刷新停，菜单栏CPU/MEM必要基础采样按设计保留，不能误判后台必要采样为泄漏或为测试停掉功能。关闭整个监控停全部，重新打开不得叠加。图标缓存须有上限与清理策略。
- 若出现暖机后持续增长，须给可复现证据并在本迁入范围修复；报告原始数据、测试时长、环境与未实测边界，不能只称来源已有测试通过。不设拍脑袋MB阈值掩盖趋势。
