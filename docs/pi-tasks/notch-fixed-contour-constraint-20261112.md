# 用户补充硬约束：歌词内部切换不能影响外轮廓

用户原话：“核心点一定是要固定刘海屏不能动，里面的切换歌词不能影响外轮廓”。

用户最新再次确认：可能不是翻转本身有问题，而是外圈没有固定，被内部翻转带动而闪动；这才是本次核查核心。优先追踪外层 frame/NotchShape/clipShape/scale/opacity 及父级 animation transaction 的依赖，明确逐句与整曲 loading→ready 两条路径。不要再以翻转参数文件无 diff 作为核心结论，也不要将上述推测写成已证实根因。请结合独立验收 `docs/reports/track-animation-cause-independent-review-20261112.md` 补齐缺口。

当前整首切歌因果核查任务仍有效，且仍仅只读；本条补充不授权立即改生产代码、动画参数或替换候选。

核查/后续最小修复必须满足：同一显示模式、同一用户交互状态下，歌词逐句短短/短长/长短/空行切换只能变化内部内容，外部黑色NotchShape的边界、尺寸、位置、缩放、整体opacity均不受歌词变化带动。不能把歌词可用性/当前行长度/行间动画直接传播成外轮廓变化。

另外，整首切歌的lyrics loading→ready也要单独记录外轮廓是否变化，明确是否与用户看到整块闪动对应；不要未经对照就认为沿用main某个loading几何分支等于符合当前用户约束。若main旧逻辑与本次明确约束冲突，报告冲突和最小解决位置，由Codex决定，不擅自改。

此约束不取消主动展开/收起、hover、显式切换歌词开关/内嵌模式等已认可行为；不要全局冻结窗口/移除原动画。用有限fixture记录外轮廓bounds/path/whole opacity与内部row变化分开断言，不只看歌词或note的墨迹框。
