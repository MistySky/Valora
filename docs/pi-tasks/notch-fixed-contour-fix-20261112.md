## Codex 决定的实现边界

1. 普通桌面刘海处于同一显示模式和交互状态、音乐活动可见且歌词总开关开启时，外层的歌词空间由稳定的歌词显示模式决定，不能由 lyrics.hasTimedLyrics、loading/ready/失败、当前行长度、空行决定。
2. 把 Models.presentationSize 中 compact quickPeek 的歌词几何条件与 showsCompactLyrics（内容可用性）分离；普通模式稳定预留现有32pt歌词区域，符合内嵌条件时稳定保留现有16pt宽度增量。保持现有参数，不增加外观样式。仅真实有歌词时挂内容；加载/无歌词时内部留空，不播放上一首旧歌词、不捏造歌词。固定slot时即使无可用歌词也保留空间，是此次授权的外圈固定行为，请明确写进报告。
3. 检查 NotchView nativeNotchSize 等所有内嵌宽度调用，保证与外框使用同一稳定几何口径。行可用性仍控制内容和时钟需求，不能因保留slot而开启无意义持续刷新。
4. 此批只修改普通桌面 compact/inline 外框的歌词依赖；锁屏位置/开关、展开播放器行为、用户主动 hover/展开收起/显式设置切换照旧。原来的歌词逐句翻转、时长、曲线、位移、透明度、音符对齐、封面翻转全不改。不得用全局禁止动画/降帧率/冻结用户交互掩盖。
5. 不夹带离屏窗口生命周期、封面内存、鼠标追踪、progress 或其它优化。若发现不修其它地方无法满足，请报告阻碍，不扩大修改。
