# V0011：逐行歌词接入既有预览区域与播放同步

先读AGENTS.md、docs/CONTINUATION-PLAN.md及docs/verification/independent-v0010-r1/decision.md。V0010成功获取与错误状态返修通过后，本任务接入可见逐行歌词。此为用户授权新增歌词内容，不宣称Alcove原有歌词功能。既有UI/控件图标/布局/动画参照原版及只读归档成熟实现，保持用户确认设置精简；不重设计播放器。

## 本批范围

1. 音乐设置只增加一项“显示歌词”，沿用既有SettingsToggleRow/卡片/强调色，默认关闭以保持未选择用户现有行为；与生产设置模型正确双向持久化，QA使用隔离域。无需添加来源、账号、偏移、翻译、字体/速度等新设置。总音乐开关关闭或歌词开关关闭取消请求/定时并恢复原QuickPeek行为；关闭时不发歌词查询。
2. 选择显示歌词后，当前活动屏在紧凑刘海下方复用现有32pt QuickPeek内容区；歌词区在有有效音乐活动时保持，不每句重复收起展开。沿用现有宽度、圆角、字体层级及灰白色，不新增浮窗或扩展到被动屏。展开完整播放器时沿用原展开布局，不另加复杂歌词页；收起再按当前进度恢复。无曲目/隐藏/音乐空闲策略仍有效，不无限保留活动。
3. 切歌提示优先约既有2秒，在同一块区域显示歌名/歌手，随后换为当前歌词；不要先收起再展开，不让新词或网络返回抢断切歌提示。切歌立即清理旧歌词，加载中/请求失败/无匹配/无歌词/纯音乐/无同步时间文本均回落当前歌名歌手，不露堆栈/错误码。不猜同步时间。
4. QQ作为首个歌词源，复用V0010-R1验证过的请求和评估逻辑，生产网络使用原生Swift6 async/await/URLSession，不从scripts启动子进程，不引入Go/第三方包或访问QQ本地数据库/账户。查询由当前系统媒体元数据显式变化触发，保守匹配专辑/时长/版本，不每次elapsed tick搜索。API/HTTP失败先拦截，不当作有效歌词。
5. 在正确隔离的actor/异步服务中实现最小缓存、请求去重/取消和过期结果保护，文件I/O不堵主线程；缓存按歌曲身份/版本区分，失败不能永久负缓存。快速A→B→A、旧响应后到、关闭/隐藏/退出、播放器故障恢复不得出现上一首歌词。启动/关闭/QA模式不意外请求网络，测试可注入歌词服务。
6. 同步使用现有播放器实际进度与播放速率/暂停状态，不建立与播放器脱节的累加秒表。暂停立刻停止换行和长句滚动，恢复按实际进度，seek前后双向定位；播放状态变化不重复搜索/清空正确歌词。对LRC多时间戳生成的非时间顺序记录做稳定时间排序，再定位当前行；空白间奏时间戳应能清掉上句，首句前/结束/越界合理回落，不将元数据标题当整首歌词。offset语义在同步使用前核对可信协议证据，不靠已有测试自证，必要修正并说明。
7. 短句不滚动；长句借用现有文字测量/渐隐等成熟实现慢速从右向左，暂停停在原位置，恢复连续，换句重置，seek重新定位。当前仅有LRC行时间，按整句显示/高亮，绝对不要平均分字假装逐字。QRC仍加密且现有合成解析器有无戳尾段补lineStart/0行为，不得消费它做逐字；真实QRC解码和字级时间验证留后续独立任务。
8. 遵从V0009活动屏归属：正常被动屏紧凑内容同步，歌词/切歌预览/滚动仅当前操作屏，切屏取消旧屏待触发内容且新屏按共享进度呈现；不能破坏最多一屏展开/拖动归属/单共享媒体服务。保留R1/R2暂停空闲期限，避免歌词开关导致音乐永不收起。
