# V0015-R1补充：沿用Alcove手形权限入口

用户最新要求：需要授权的设置像Alcove一样加“手”标志，点击进行授权处理。仅接当前已有功能，不迁入其他模块/权限占位，不自创新设置风格。

直接沿用归档Sources/AlcoveRevival/SettingsControls.swift的SettingsToggleRow：hand.raised.slash.fill位于开关旁，blocked时开关禁用，onAccessory为权限入口。本Valora组件已保留这些接口，但当前功能尚未接好。不要另画图标/改行高间距/新建权限中心；归档部分onAccessory只是“后续接入”notice，不能机械照搬成假功能。

范围与行为：

- 核对当前设备蓝牙检测、实时波形的系统音频读取所需权限及真实状态；登录时启动如确需系统批准则依据SMAppService.requiresApproval处理，不能把它当蓝牙/TCC。普通歌词/外观/悬停等无需权限的项目不加手，不给每个开关乱加。
- 未授权/被拒绝/受限时按真实状态显示原手标志和可访问性“需要授权”；点击手后：未决定时由对应正式系统API发起用户主动授权；已拒绝时引导对应系统设置；返回应用后重新确认，获准才恢复正常开关，标志消失。不能先保存开启却无实际能力，不能每轮poll重复弹窗。
- 不擅自假定IOBluetooth.pairedDevices一定弹窗；只读查公开文档/SDK并说明权限状态查询依据，不为造授权提示更换成熟检测架构/扫描/连接。当前蓝牙用途声明补充同轮一起做。
- 实时波形使用现有LiveAudioTap实际路径，系统音频与屏幕录制权限不可无证据混用；禁止私有TCC读写或仅靠错误码猜全部权限。若当前API无法可靠预读授权状态，明确unknown并保留可用的用户主动尝试入口/错误反馈，不用硬编码blocked永远封死。按具体平台能力做最小适配，不架构重写。
- 外观设置已要求移除，设备页仍只有总开关；手形只是该行的原版权限附件，不新增外观/权限开关。授权状态与功能总开关分离：授权通过不代表自动开启所有功能，关闭不撤销系统权限。

验证必须用可注入状态/请求与打开设置spy：未决定/拒绝/批准/受限/unknown、点击手、返回刷新、开关失败回滚；QA不真实触发/接受权限弹窗、不改TCC/系统设置/登录项，不实播/连接设备。截图比对原手形位置，区分fake状态和真实授权待验。
