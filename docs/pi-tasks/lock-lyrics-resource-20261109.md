# 锁屏歌词资源优化（Codex 派工，2026-11-09）

用户已实测当前桌面鼠标 CPU 优化有效，并接受当前桌面歌词版本（运行候选 build43）。本批只做锁屏歌词资源优化，沿用现有 Pi 会话、模型、分支。完成后停等 Codex 独立验收。

## 实施决策

1. 先读 LockMusicView/CompactLyricsView、NativeLyricsRow/LyricsRowExperiment 和锁屏呈现生命周期，说明现有锁屏每帧触发的工作与桌面缓存渲染的区别。歌词是待验证的主要嫌疑，不能预先宣布就是根因。无真实锁屏基线时如实记录，不能拿预览假装实机。
2. 优先复用现有 native 歌词渲染底层（字形/图像/度量按行缓存，每帧仅更新高亮 mask 和必要的横向阅读位移），不要复制第二套解析、时钟、渲染器，不重写整个锁屏。
3. 锁屏接入独立的呈现 active 条件：锁屏卡片实际呈现及进退场期间正确运行；卡片退场结束、隐藏、关闭歌词、功能关闭、解锁清理后取消时钟/边界唤醒并释放会话。绝不能直接复用桌面的 notchSurfaceOnScreen 作为锁屏可见条件。暂停保留当前行和进度，静态行需要的下一句单次唤醒不能丢失；后台不用常驻定时器轮询。
4. 现有实验渲染编译边界继续保留；若当前交付候选使用 VALORA_LYRICS_EXPERIMENT，锁屏同一候选也通过明确实验条件接入并保留 CompactLyricsView 回退，正常 Release 不能无意带入实验实现。
5. 保持锁屏外观与功能：卡片尺寸、位置、玻璃、配色、字号、音符位置、无歌词/空行音符居中、暂停保持展开、歌词开关进退场、音量与播放器交互均不改。换句仍新句由下进入/旧句向上离开，0.2 秒、±26pt、easeInOut 与淡入淡出；长短句切换不引入末尾跳位/二次收缩，不照搬桌面容器 max(新旧宽度) 结束时突然缩宽的隐患。保留逐字同步、横向滚动、切歌/seek/歌词替换的正确性和失败回退。
6. 不碰已通过的桌面鼠标路径、刘海动画和桌面布局；不改 Space 归属、激活/焦点、登录区域、锁屏布局。必要共享底层修改需说明桌面影响并覆盖回归。
