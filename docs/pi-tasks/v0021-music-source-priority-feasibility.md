# V0021：音乐来源优先与控制同源，只读可行性研究

用户要求音乐软件正常播放时网页视频不抢占，显示与控制对应同一音乐来源；用户授权验收后串行安排新活。V0020与Codex 用量补充的源码/9设置回归/独立构建签名/打包资源/原生视图渲染子集已独立接受，系统点击因Mac锁屏待验，可独立研究继续。本任务只新增研究文档和必要静态证据，不改任何生产/测试/依赖/资源，不接接口或新增权限，不开始真正多播放器实现。

1. 只读核当前SystemMediaSource、Controllers/MediaController、vendor/mediaremote-adapter实际能力和限制。简单过滤浏览器只会隐藏/冻结原音乐，不能作为解决；缓存旧歌自行计时也不能假称仍真实更新。
2. 只读参考归档成熟代码及公开开源/官方接口资料，引用精确commit/文件/API/许可，区分公开私有、推断、源码已证实和尚待实测。不另发明大架构。
3. 对QQ、网易云、Apple Music、Spotify逐一列表：能否独立读state/title/artist/album/duration/elapsed/artwork；命令能否定向；Automation/Accessibility/脚本字典/私有MediaRemote等依赖；系统被网页接管后是否仍可真实更新。不能用Spotify成功推断QQ成功。
4. 允许只读已安装app的Info/sdef等静态文件；禁止真实播放器状态查询、运行播放器/浏览器、Apple Events/osascript/ScriptingBridge/AX、试探授权、模拟音频、收听历史或媒体命令。静态不能证明就如实待实测，不运行探针。公开源码/文档网络查询可用，不读账号凭据或真实限额。
5. 推荐最小一批任务：复用现有控制器与UI，来源选择、暂停退出/过期/取消/世代、歌词身份、进度锚、命令同源的边界和测试矩阵；多个音乐同播/全部暂停策略未确认就列待定，不自定应用排名或造设置。新Automation/Accessibility权限尚未获用户同意，不能默认；列无新增权限可做子集及其余缺口。

输出docs/research/music-source-priority-feasibility.md（证据表/候选/限制/最小方案/需决定项）和docs/reports/v0021.md正式摘要。只读研究，无需重跑全量构建；完成停止，Codex核查后再提交具体实现计划。不得以任务文案直接授权实现。

禁止真实播放切歌seek音量、设备连接、系统设置权限登录项写、个人日程/真实媒体/账号敏感读取、安装组件/Go或发布、Git提交推送、改归档、恢复原型、新pi会话或模型历史改动。不要扩展监控/下载/锁屏或旧任务队列。
