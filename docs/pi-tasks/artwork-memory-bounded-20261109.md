# 封面内存优化（仅在Codex派发此文件后执行）

当前歌词动画返修验收优先。本文件预备，不代表已开始。收到Codex mailbox正式派发后才执行，沿用当前Pi会话/模型/分支，保留所有工作，不提交推送。用户明确要求不影响体感、不改变动画。

## 已确定范围

仅处理封面准备链路：Controllers当前NSImage(data: 原始Data)；ArtworkPalette.extract当前image.tiffRepresentation后SHA256，再取CGImage缩成32×32提色。全尺寸TIFF是可证明的额外准备，巨大封面有峰值风险。当前真实physical footprint约60—84MiB的单次数据没有证明泄漏或紧急性，不做全面内存重构。

### 改法

1. 从**压缩原始Data直接通过ImageIO thumbnail API降采样**，不是先拿完整CGImage/NSImage解码后用CGContext缩小。按实际最大封面56pt及Retina倍率选择明确像素预算，建议256px有余量；必要更高上限需说明真实显示输入。不要将pt和pixel混用，不放大小图，保持纵横比、方向、透明度、色彩空间正确。
2. 新图片由现有封面、过渡和纹理链共享，保留当前current/target/queued的有界过渡。不要给每个视图各解码一份，不增加第二套长驻缓存。保留媒体source的原始Data协议与既有去重；Data的共享引用不等于多份物理拷贝，不据字段个数算收益。
3. 去掉生产封面identity生成中的整张TIFF序列化。采用一次性、稳定的封面视觉内容身份（适当分辨率的规范化像素或经验证方案），与调色板分开：**不能只用32×32提色图/颜色列表当唯一封面ID**，不同封面可能同色/粗图相似；也不能不加说明改用原压缩bytes使同图不同编码/metadata就误触发翻转。保留相同封面稳定identity、变更封面及时替换、迟到/缺失封面占位与queued规则。
4. 调色板仍用原有32×32/相同桶和选择规则，不改进度条色彩风格。降采样可能改变边缘/提色，必须比较：方向、颜色管理、alpha、非正方形、已有原图路径与新路径在真实56pt@2x输出的差异，阈值说明，不声称数学上完全无损。
5. 仅在封面Data/有效输入变化时准备一次；不按progress tick/歌词frame重复解码。新的准备结果和identity/colors保持同一封面版本，迟到处理不能把旧封面写回。AppModel用于开发/测试的直接NSImage赋值入口兼容，不引入全局高频广播或取消当前异步规则。
6. 禁止改变翻转方向、时长、曲线、可见尺寸、圆角、标题滚动、歌词动画、锁屏位置、主从歌词开关；不动截图窗口/SwiftUI基线/AirPods视频/媒体helper，不扩展到其他内存项目。

## 验证

- 用少量确定性fixture验证大图实际解码像素上限、方向/透明/比例/颜色、相同视觉不同编码身份稳定/不同图片不混淆；未知/损坏数据正确回退，切歌缺失→迟到→快速queued封面仍正常。
- 一张较大静态封面（例如3000×3000）在原路径和新路径的一次性对照，记录原始像素/压缩字节与准备后字节估计；若没有真实footprint测量则只称估算，不冒称用户稳态减少几十MB。禁止压力/批量闪窗/重复循环切歌。
