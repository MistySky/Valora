# 提案 V0024：只读验证后台音乐来源（未授权执行、未投递）

## 需要用户先确认

是否允许一次有界的真实媒体只读查询，用于确认能否在浏览器接管系统当前播放时，仍读到后台音乐客户端。当前仅提案，禁止自行运行或投递。

## 最小范围

- 先静态复核归档per-client路径和macOS27可用符号/调用约定，再独立隔离进程验证；不改运行中的Valora，不引入Go/账号SDK或额外来源选择UI。
- 只查询当前已运行媒体客户端，不启动播放器或浏览器、不发送播放/暂停/切歌/seek/音量命令，不设置系统媒体默认目标。
- 一次进程有总超时、有限样本、立即退出，不常驻、不安装服务。只记录客户端bundle ID、字段存在性、是否有独立时间锚/更新、错误与耗时，不保存歌名/歌手/封面/收听历史或账号内容。
- 不申请或修改Automation/Accessibility/蓝牙/日历/TCC等权限，不读取凭据。如果接口必须新权限或运行环境不支持，记录限制后停止，不绕过。
- 用户如需验证浏览器接管，自己操作播放；探针只读观察。不能因一次client查询成功就宣布控制同源已实现；定向命令先做静态和spy核查，真实媒体命令另需授权。

## 交付与停止条件

只回答当前macOS27能否识别后台音乐、字段是否完整/持续更新、已知权限/私有ABI限制。报告给用户后再决定实现方向。无法验证则保持现有system current，不用缓存旧歌/过滤浏览器假装满足，也不换成丢进度封面的QQ弱AX方案。
