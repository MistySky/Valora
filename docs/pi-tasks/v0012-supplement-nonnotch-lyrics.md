# V0012最新补充：无实体刘海屏统一宽度，歌词与模拟开关解耦

用户最新已明确要求并授权告知pi：无实体刘海屏的模拟刘海和普通胶囊统一宽度，歌词显示不再受强制模拟刘海开关控制。此规则覆盖此前“非刘海紧凑不显示歌词”的补充，不要按旧规则禁用普通胶囊歌词。

同时先读并执行docs/pi-tasks/v0012-priority-lyrics-reference-review.md，优先参考成熟获取/匹配实现并修知否知否覆盖问题，不引入Go；该研究与本补充同属V0012，不另开产品模块。

## 当前最终几何与显示规则

- 按每块屏幕硬件分别判断：有实体刘海的屏幕保持硬件几何优先，不套用固定214pt或覆盖原生宽度。
- 只针对无实体刘海屏：模拟刘海和普通胶囊播放音乐时的紧凑可见总宽度统一214pt，展开总宽度统一345pt（pt而非物理像素）。无音乐时也应统一两种形态对应的基础宽度；建议基础宽140pt、音乐增量74pt，但须按现有几何链路实现并实测总宽，不能只把geometry.compact改140却仍加胶囊62得到202pt。
- 保留形状差异：模拟刘海贴顶并保留肩部，普通胶囊保持圆角和既有顶部间距/高度策略。不能为取得相同宽度伪造hasPhysicalNotch=true，不能顺手改真实刘海尺寸或所有通知模块。
- 强制模拟刘海开关只改变无实体刘海屏的外形，不作为歌词能力/请求开关。歌词总开关开启且在3秒内取得有效歌词时，两种紧凑形态都支持既定小区域歌词；未取得/超时仍隐藏且不留空条。
- 展开后两种形态都可显示最底部歌词，音量在其上；紧凑/展开使用同一歌词进度和缓存。形态切换不得清空有效歌词、重复搜索或重置3秒预算。
- 当前活动屏可显示动态歌词，其余被动屏保持紧凑常规音乐内容、不跟着多屏一起展开；每屏命中/geometryOverride/宽度/内容布局必须一致，透明外仍点透。
