# V0024：已授权，只读实测后台音乐客户端

用户在“下一步先只读验证网页接管后能否继续获取后台音乐，不控制播放、不改系统权限”的明确询问后回答“可以”。这授权本任务有限真实媒体只读查询，覆盖V0021仅静态/禁止真实媒体查询的限制；不授权真实媒体写命令、启动/控制播放器浏览器、系统权限/账号读取、生产多来源实现或恢复定时器。

先读AGENTS、docs/verification/independent-v0021/decision.md、docs/research/music-source-priority-feasibility.md及proposed-v0024-per-client-read-probe.md。提案的“未授权执行”历史状态已被用户本次明确授权覆盖，实际执行以本任务为准，不修改历史提案或已发任务hash。

## 目标

确认当前macOS27是否能按客户端识别已运行后台音乐来源，以及title/artist/album/duration/elapsed/artwork/playback state是否存在、独立更新。当前system current不能定向读/控制，简单过滤浏览器或缓存旧歌计时不是方案。未验证不得宣称不可能或成功；查询成功不证明控制同源已解决。

## 执行方式与边界

1. 静态复核归档per-client API/符号/参数ABI后，使用独立隔离进程探针，不改Sources/Package/scripts/package.py或正在运行Valora，不创建常驻服务，不安装发布。可用已批准vendor/本地构建工具链及必要Swift/原生ObjC ABI适配的测试harness；不引入Go、新库或降低签名/安全保护，不改系统framework/系统二进制，不重写任何授权/entitlement绕过访问控制。明确区分已有system adapter路径与新per-client实验。
2. 总共一次有界批次，最多3个样本，约1秒间隔，整体硬超时不超过10秒；每个异步callback有截止/进程退出保护，不跑无限stream、不无限换签名/猜ABI/反复尝试。符号/调用约定不明确或需要新权限则记录限制停止。
3. 只读当前已运行客户端，禁止启动播放器/浏览器、发play/pause/next/previous/seek/volume、设置默认媒体目标/来源、发模拟音频/键鼠控制播放器。不能为制造浏览器抢占场景自己播放视频。没有真实并发场景就明确该场景未验证，先交付现有可读性证据。
4. 不请求/修改Automation/Accessibility/蓝牙/日历/TCC/登录项或系统设置，不读凭据/账号/历史日程。若系统出现授权窗口，不接受、不重置权限，报告阻塞。
5. 结果只记录客户端bundleID、字段存在性/数据类型、是否有有效时间锚、时间值是否随样本变化、艺术图是否有payload及大小级别、client数量、错误/耗时。禁止在日志/文件/终端保存歌名、歌手、专辑、封面、收听历史或账号内容；实际payload仅在内存分析后释放，不把完整dictionary/JSON倾倒进工具输出。
6. 不做实际定向控制验证。可静态/spy核控制路径，所有真实媒体命令仍需另行授权。不得用只读per-client能拿到数据推出可安全发送定向播放命令。

## 结果与下一步

输出docs/reports/v0024.md与docs/verification/v0024/：可审查的harness源码/构建命令、脱敏结构化结果/运行退出码与超时、API出处/已知私有ABI限制、当前客户端是否具备浏览器/音乐并发条件、字段完整性和更新证据。若读不到，区分符号不存在、clientCount=0、无当前客户端、权限/调用错误或超时，保留证据，不直接泛化“所有无权限路径不可能”。

结尾给出最小实现建议或需用户手动操作一次的验证步骤（比如用户自己播放网页视频后再授权一次只读采样），不修改生产、不自动进入SourceCoordinator/多来源adapter/新设置/新权限。保持当前QQ进度/封面/歌词体验，不为接独立源换成字段残缺AX。完成停止Codex独立复核，再决定实现。
