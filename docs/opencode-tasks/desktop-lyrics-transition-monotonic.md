# 换句实验：按真实时间推进，保持原版体验

用户指定新 OpenCode 会话使用 GLM-5.3-Flash；Codex 确定方案并验收。读 AGENTS.md（旧会话/模型条款已被用户覆盖）及 `docs/reports/desktop-lyrics-transition-runtime.md`。保留鼠标预筛选修复、音符居中、空行及现有缓存；不改锁屏。

## Codex 审查发现与指定修法

`Sources/Valora/LyricsRowExperiment.swift` 的 `LyricsRowExperimentHost.startTransition` 每次 60Hz Timer 回调都累加固定 1/12；一旦主线程卡顿、回调合并或丢帧，0.2 秒的动画仍要等满 12 次回调，会被拉长，与用户要求的原版体感不符。已知 60Hz 帧数测试只能证明无延迟情况下的插值，不能证明真实时长。

1. 以单调时钟记录本次换句的实际开始时间；每次回调用 `(now - start) / 0.2` 计算并夹取进度。回调延迟到期后第一次执行立即到达终点、停止计时器并释放旧句；不能用 Date 墙钟，不能逐帧增加固定份额。保留已有平滑曲线、±26pt、双向透明度，不修改歌词的 30Hz、字体、颜色和滚动。
2. 引入可注入单调时钟或等价测试 seam；写独立行为回归：开始后只触发一次但时间已过 0.25s 必须立即 settled 并释放旧句；0.1s 进度与按时间计算一致；跳帧/间隔不均、快速 A→B→C、暂停 seek、隐藏/卸载、捕获失败与旧回调不得重启动画。不要依赖睡眠是否准时，不删除/弱化既有断言。
3. 核对现有新旧行首尾、音符居中、空行→下一句及单个活动歌词时钟；静态视口只在换句持有，逐帧不重新抓图/构建文字。60Hz 仅在过渡期存在，定时器的 lifetime 必须可验证。正常构建无实验实现，锁屏继续旧路径。
4. 针对开屏歌词运行时与原版过渡中间帧，记录已有证据和目前未验；只有在一致时才说一致，不以端点或计数推导完整体感。CPU 改善是用户对 build32/33 的观察，新代码未实测。

运行相关实验构建测试和普通 Release 隔离检查，报告 `docs/reports/desktop-lyrics-transition-monotonic.md`，精确报告通过/跳过/失败和风险。不得对鼠标命中预筛选、音频、设备或锁屏进行其他修改；不控制真实播放、不启动/替换 App、不打包、不提交。完成后停止，由 Codex 独立验收。
