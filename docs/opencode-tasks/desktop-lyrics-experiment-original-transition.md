# 桌面歌词实验版：恢复原版音符居中与换句体感

用户实测 build32：CPU 已明显改善，但小音符一直靠左，换句动画不如原版。用户要求体感与功能保持原样。沿用现有 OC 会话/模型/分支，读 AGENTS.md 和 build32 报告。不得替换当前运行实例。

## Codex 分析与指定方案

1. **音符位置**：现版 `LyricsLineExperiment.swift` 的 `NativeLyricsRowHost.frame(width: availableWidth)` 对所有行固定撑满，而生产 `CompactLyricsView` 对短句用文字自身宽度包裹，音符 + 文字整体居中；长句才占满可用文字宽并靠前。保留生产 `LyricsLineMetrics` 的长短判断；短句容器使用 SwiftUI 实际绘制内容宽度，长句使用 availableWidth。内容/文字宽变化时只在换句或静态输入变更时传递更新，不能让外层随 30Hz 动画重算。保留音符、5pt 间距、行高、padding、裁切、空行和无音符内嵌原语义。
2. **换句体验优先采用原版 SwiftUI transition**：保留已有按行准备静态 SwiftUI 文字图像、逐帧原生 mask/位移的低开销路径，但把“新/旧行换句”的呈现交给 SwiftUI 层，复用生产 `.asymmetric(insertion: .offset(y: 26).combined(with: .opacity), removal: .offset(y: -26).combined(with: .opacity))` 和 `.easeInOut(duration: 0.2)`。只在真实换句更新一次视图身份与出入栈；旧行使用切换瞬间的静态快照，不保留第二条活跃 30Hz 时钟或抓图循环。禁止新旧两套换句动画同时作用。按生产行为处理首行、空行、快速连续换句、暂停、seek、切歌/过渡中隐藏；失败继续完整回退生产行。
3. 如果上述方式不能保证正确、出现双计时器或吞字，记录具体阻碍后停止，不擅自降低刷新率、改歌词、字体/间距或换效果，不使用拍脑袋调整动画参数。

## 验收

- 独立宿主单个复用离屏画布，对比真实生产行与实验行中小音符的**具体位置**、文字起点、组合居中坐标（不要只计算整张图差异）；覆盖短句、长句、无音符内嵌、空行、长短句切换及宽度变化。断言误差以实际 2x 下 1px 为上限；不能声称未测到的 1x 通过。
- 换句采集原版与实验版的 0/50/100/150/200ms 关键帧：以同一可控动画时钟或明确同步手段，测出新旧行相对位置和透明度；若无法同步，报告不能证明体感等价，不用计数代替。覆盖短→长、长→短、快速连续切换；记录资源释放。
- 连续 30 帧无逐帧重建文字、SwiftUI 换句身份或重新抓图；无双时钟；保留失败回退、seek、播放锚、隐藏恢复和锁屏旧路径，跑相关回归。普通 Release 不能带实验 renderer；实验构建可用。
- 输出 `docs/reports/desktop-lyrics-experiment-original-transition.md`，记录具体差异、测试与未验项。CPU 降幅是用户对 build32 的观察，不能把新改版的 CPU 当作已测。禁止启动/替换、安装、真实播放控制、提交推送；完成后停止等 Codex 独立验收。
