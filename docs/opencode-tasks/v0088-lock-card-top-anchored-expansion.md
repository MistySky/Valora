## 用户最终意图

“其实效果肯定是和刘海屏那个效果一致的。”指交互和几何原则，并非把锁屏卡换成黑色刘海形状。

1. 卡片顶边、封面、歌名、进度条、播放控制行的位置固定；展开/收起不能让整个卡片或这些已有内容上下移动。
2. 音量和歌词独立展开收起：可见玻璃外框只向下长高、从底部收回。收起必须收回整段布局高度，不可用 opacity=0 保留空槽冒充。
3. 控制行左侧音乐按钮负责歌词展开/收起，与右侧音量入口对应；底部歌词沿用 CompactLyricsView，保留其音符与居中规则。不把底部孤立音符作为折叠后的占位。
4. 顺序：固定播放器内容 → 可选音量 → 可选歌词，歌词始终最底部。现有全局显示歌词开关仍控制功能；无有效歌词不新增空白槽或伪歌词。
5. 设基础可见高度 H、音量区 V、歌词区 L（均包含实际间距）：四态高度应为 H / H+V / H+L / H+V+L；顶边坐标一致。折叠某区可正常带动它下面的区移动，上方播放器不得移动。宽度/圆角和当前成熟 UI 保持。
6. “预留高度”是初始布局为最大展开状态留足屏幕空间，避免覆盖登录用户区域；不是常驻可见空白。透明宿主窗口可以固定并留足空间，可见玻璃外框按内容伸缩。初始位置不能每次按当前高度重新居中，不能居中锚定缩放或人为 Y 补偿掩盖问题。使用现有可确定的屏幕/布局边界，不读取账户信息、不操作真实登录界面；无法证明的系统登录区域安全边界如实列待验。
7. 动画参照项目当前已接受刘海播放器的音量展开收起路径，先读实际代码：复用合理的上锚布局/转场，不仅写“和刘海一致”的注释。支持四态及快速反转，无跳动、裁切和遗留空白。
