# V0098 限定收尾：锁屏玻璃/预览焦点生命周期

现有会话继续；V0097/R1已独立接受，当前唯一运行0.2.0(3)，构建号以后每个正式候选继续+1。Objective-C及Perl用户明确决定保留，本轮不重写媒体或native桥。

当前锁屏activateGlassSurface主动.regular+activate+makeKey，退出只.accessory；LockCardPreview同构。用户当前功能认可，不能为清理丢失玻璃/动画/布局，更不能“恢复焦点”时重新抢系统登录或用户新选择的应用。

## 范围
1. 先静态核真实锁屏与preview进入退出、禁用、sleep、快速反转、stop/quit全部调用链，解释现有激活动作具体用途。注释“只有key窗口才有玻璃/原版也如此”未被充分证实，改为本实现观察/取舍，不扩大为系统绝对限制；不以猜测删行为。
2. 最小明确激活所有权/会话：保存进入前真实activationPolicy，只有本次确实改动后才恢复，重复进入不覆盖原状态；未进入的stop不得擅自改变策略。真实锁屏与preview不能互相过早恢复对方仍持有的策略，避免无条件硬编码accessory。
3. 恢复先前应用必须保守：仅在本次确实激活Valora、用户会话已解锁/非锁屏、当前焦点仍属于Valora、原应用仍有效时允许；用户主动切到其他应用后不得抢回，锁屏登录窗口持焦时不得激活记忆应用。恢复不足证据时宁可只恢复策略并记录待验，不能承诺“密码焦点已修”。不读/记录个人窗口标题/账号，不使用AX新权限。
4. 能独立验证的状态判断用注入fake应用标识/策略/动作spy，不实际激活其他应用或真实锁解。保留当前darkAqua/variant5/结构、原锁解动画、选屏/位置、歌词/音量、开关及UI。不要引入通用焦点框架或全局重构。
