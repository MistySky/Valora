用户明确：OpenCode负责执行，优化位置和实现方向由Codex决定。此任务覆盖此前“自行判断下一步”的开放要求。遵守AGENTS.md；保留现有分支与第一批有效改动，不提交/安装/替换，不进入锁屏专项。

2026-11-07复核补充：本地已有 seek-drag-anchor.md 与 Controllers 中的乐观seek改动。必须保留该用户另行请求的修复，原型的播放锚输入应沿用当前模型，覆盖拖动落点/失败回滚/确认，不直接读取旧系统快照而绕过PendingSeek。该seek修复尚不等于本轮歌词性能改进。

## 决策与范围

实测build29歌词开启持续高CPU，关闭约2%；缓存小优化没有证明能解决目标。下一步指定验证并实现“歌词行的每帧更新独立于SwiftUI视图构建”，不是降低30Hz或改变动画。它是待实测的工程方案，不得称已证明根因或保证降幅。

只涉及歌词行渲染，不继续改波形、音频、设备、菜单栏、窗口扫描或锁屏。先修正确性，再完成独立原型；原型未通过视觉与行为等价验证前不切换生产路径。

## A：先修缓存失效

读取 docs/reports/desktop-playing-cpu-lyrics-followup-independent.md，运行其中两个独立失败测试。
现有nextIndex/nextStart/lineCount不是时间轴身份，必须废弃这种有效性推断。最小正确修复：检查缓存之前先按当前时间轴求出真实后继起点，将该起点纳入比较，保留度量/标签缓存；接受临时恢复一次行尾查询成本，不能以性能理由保留错误。若用二分查找，必须严格实现第一个start > 当前行start，同时间戳、前奏、末行和非有限输入遵循现有逻辑。禁止新增每帧全时间轴字符串/hash。

## B：指定歌词行原型，不替换当前生产路径

新增独立的原生歌词行renderer及debug-only预览/隔离验证入口，暂不把CompactLyricsView生产路径改为新实现。实现目标：

1. 上游提供不可变显示快照：歌词时间轴/歌曲身份、播放锚时间与进度、速率/播放状态、duration、可用尺寸、强调色与显示选项。更新源沿用现有权威快照和歌词锚。renderer不直接订阅整个AppModel，不主动查询系统媒体。
2. 使用原生NSView/CALayer容器。文字在换句/文本/字体/颜色/scale变化时准备一次，缓存灰色底字和强调色字的静态内容。连续高亮只改强调层mask宽度，长句只改共同容器的位置。每个30Hz tick不能重建SwiftUI Text树、重新量字、分配整行标签或创建位图。
3. 复用现有LyricsLineMetrics、LyricsLineLayout、歌词时间锚及词进度公式。不要重写歌词业务、解析或网络。时间轴求当前行与真正后继，支持向前/向后seek和倍速。
4. 显式保留原有高亮/滚动、17pt行高、12pt semibold、padding/裁切/居中语义、0.2s easeInOut换句与±26pt位移、暂停保持行、空白句、无歌词音符和无障碍。当前SwiftUI文本实际字距与metrics使用kern0.05可能不同；必须检查实际输出，不得把测量参数想当然作为可见样式。不同backing scale及中文/英文/emoji都要比较。
5. 保留30Hz时间分辨率；稳定的空内容可以不持续tick，但恢复加载或时间进入下一句不得漏事件。可见性暂停/恢复要显式控制，禁止仅用window != nil推断可见。保持线程主actor约束，stop/deinit释放定时器和资源。
6. 原型内更新mask/位置避免意外隐式动画，按原公式逐帧更新；换句动画单独保持已有曲线与时长。不要为了性能改变波形/歌词视觉。

## 验证与交付

- A两个独立回归必须转绿，跑相邻歌词缓存与时间轴测试。
- B使用同一注入时间、同一歌词/尺寸/scale对比原实现与原型的输出；覆盖逐字中点、跨词、句切换前后、长句滚动、纯LRC、重复时间戳、暂停、seek、倍速、末行、空歌词。发现排版/基线差异就记录并停止接入，不用“肉眼差不多”自称等价。
- 测量原型的帧更新工作、文本重建次数、布局次数；CPU须在可比有效环境测，否则标明未验。离屏TimelineView不节流的旧实验数据不得用作基线；不依据sample等待栈估计CPU占比。
- 不启动额外App或操作真实播放，必要的实机对照交Codex协调；用户要求单实例，不得与当前程序并行。
- 新增报告 docs/reports/desktop-lyrics-renderer-directed.md，明确A已修/B原型状态/等价性差异/性能证据和未验项。原型完成后停下，Codex决定是否接入生产；不得自动接入、打包替换或扩下一批。
