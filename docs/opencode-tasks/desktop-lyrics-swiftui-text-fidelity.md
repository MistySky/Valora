# 下一阶段：保留 SwiftUI 字形的静态文字缓存原型

用户要求继续，核心约束始终是不影响体验、不影响功能。Codex 决定本批方案，OC 执行。沿用现有会话/模型/分支，先读 AGENTS.md 和 R4 独立报告。

## 决策

停止通过 CATextLayer 调字体/字距来追赶生产画面。新增一个隔离可选文字后端：**SwiftUI 按现版样式准备静态文字图像，原生图层逐帧仅更新遮罩和位移**。生产 CompactLyricsView 保持原样，R4 的选行、播放锚、生命周期、边界时钟、动画所有权全部复用，禁止复制第二套时间状态机。

## 精确实现边界

1. 在开发原型中添加明确的文字后端选项（现有 CATextLayer 与新 SwiftUI 静态图像），默认仍保留现有后端以便对照。实现可在独立 debug-only 文件中，但共享 R4 原型的调度/选行逻辑。不得接入正式 CompactLyricsView。
2. 新后端使用持久复用的 NSHostingView 绘制静态 Text：沿用生产的 `.font(.system(size: 12, weight: .semibold))`、`.lineLimit(1)`、`.fixedSize(horizontal: true, vertical: false)`，底字 `.foregroundStyle(.gray)`，强调字 `Color(nsColor: accent)`。不额外加 kern、描边、粗体、阴影，不改生产样式。用 SwiftUI 实际布局得到文字尺寸；业务填充和滚动计算仍用既有 LyricsLineMetrics/Layout，不统一或重写测量口径。
3. 仅在文字/字体/实际绘制色/显示倍率等静态输入改变时准备底字与强调字的透明 CGImage，赋给原生图层 contents。复用 hosting 容器，不为每句创建/显示新窗口。不得在 30Hz 帧内抓图、修改 hosting rootView、量字或生成位图。NSHostingView 离屏缓存若不能得到可靠输出，明确报告限制，不悄悄切回 CATextLayer 冒充新后端。
4. 缓存只保留当前行和退出动画行的图片，引用共享可行时共享，不做每行永久缓存；退出动画结束与 stop 清理。记录实际图片像素尺寸与估算字节，不能以缓存所有歌词换 CPU。不要裁掉长句内容来省内存。
5. 复用既有 mask/position 动画路径。新后端的几何/基线从现版 SwiftUI 17pt 行容器推导，**不要照搬 CATextLayer 的 -2pt 补偿**。改变后端不得引入新的缩放/半像素取整策略。出栈层保存同一静态图像、原横坐标、当前 mask 与滚动状态，保留 0.2s easeInOut、±26pt 和双向透明度。
6. 无障碍沿用 R4 的当前行回调，不把位图当作标签。时长/时间轴/宽度仅改变行尾或布局时，不重建无关静态文字。字体/实际显示倍率改变可重建，但每帧不能重建。

## 验证：先小范围证明方向

- 本批仅验证新后端是否解决已观察到的字形偏细，不接入正式版、不测无效的离屏 TimelineView CPU。
- 为新后端跑 R4 独立逻辑回归的等价覆盖（复用参数化更好，原断言不删不弱化）。重点逐字和长句、换句、seek、暂停、宿主重绘、隐藏恢复、静态边界，以及 61 秒有效锚。
- 保持单个可复用隔离窗口/画布，不批量开关窗口，不影响真实媒体。截图采用相同时间/颜色/尺寸/实际 scale，生产参考和新后端都保存 PNG 和差分统计。捕获失败、空白图像、图片写入失败都必须使测试失败。
- 首批可只做实际 2x 下三个场景：中文短句；逐字半词填充；真正发生位移的长句。长句必须有明确后继，如 0→8 秒，在第 4 秒比较，并断言 offset > 0。旧探针只有末行且 elapsed=0.4/duration=240，尚在 15% 停留段，不能称为已测滚动相位。
- 比较原始 PNG（不先对齐/缩放来消除差异）。分别报告位置/基线/墨迹、颜色和遮罩边缘；字形较粗/较细是否解决由证据决定，不用“最佳整数位移为零”推出完全一致。1x/emoji/过渡帧未做就保留未验。
- 连续 30 帧在同一句内：新后端文本准备次数、hosting rootView 更新次数、位图生成次数都为零增量；只 mask/offset 变化。换句仅准备一次。停止后确认活跃时钟/出栈缓存释放。报告新后端的准备成本与内存估算，不能把计数当 CPU 降幅。
