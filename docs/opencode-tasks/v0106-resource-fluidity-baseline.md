## 本轮边界

只做基线测量、原始证据与局部开发测量工具必要适配。先读AGENTS及当前计划；旧V0014仅可参考，不执行旧队列。此任务是当前用户对资源专项的授权，覆盖“阶段尚未到不能测量”的旧条款；仍禁止批量闪窗、反复开关压力循环。不要先优化生产实现、改UI/动画/刷新节奏、删除测试或升级依赖。发现问题给证据和最小建议，停等独立验收。

保留正在运行的build15，不退出/替换/覆盖dist、不再启动第二个正式Valora实例。开发测量用独立身份、隔离偏好与fake服务，仅一个持续存在的QA视图宿主；若现有入口无法保障，先静态核查入口并增加debug-only隔离适配，不能冒险运行生产入口。不得触发真实媒体/控制/日历和账号读取、系统权限/登录项、设备/锁屏操作，不安装、不Git提交推送。QA需无权限、无真实网络、无菜单栏status item、不抢焦点。无法保证真实视图安全则执行可隔离部分，明确缺项，不以离屏图冒称真实窗口动画。

## 测量顺序

1. 先确认现有FluidityAudit、LaunchPolicy、AppDelegate入口隔离，记录Debug/Release区别和仪器成本。采样输出批量落盘，不每帧日志；测量工具自身不在生产启用。
2. 稳态：全部模块关闭、fake音乐播放紧凑、暂停、歌词隐藏/音乐关闭；每态预热后约30秒，CPU累计时间差/墙钟计算（单核100%口径）、RSS分布/末值。记录可获得的物理footprint与唤醒/回调；取不到的写不可用，不猜值。每秒取样即可。证明关闭音乐timer停止，暂停/隐藏歌词不持续刷新；不要声称整个进程零CPU。
3. 交互：一个窗口内依次各做一次展开→音量展开→收起、短句换句/长句跟随/fake切歌翻转、锁屏音乐卡模拟扩展（若安全入口存在）。观察或测量主线程调度、callback间隔p50/p95/max，CPU峰值、RSS变化；不是连续开关/闪窗。真实锁屏动画不操作，标待用户体感/系统工具条件。
4. 保持一个fake播放视图约3分钟，之后暂停稳定30秒，检查内存趋势和CPU回落；总一次运行尽量不超过10分钟。不要无证据重复运行。
5. 帧指标明确区分Timeline/CADisplayLink回调、绘制、实际合成呈现；没有呈现数据不能写60fps或与Alcove一样流畅。不要自动控制原版Alcove做真实媒体对比。记录硬件、系统、编译配置、显示刷新率是否可知、采样方法与限制。Debug结果不能等同Release正常资源成本。

如发现入口/测量代码失败仅限修工具，针对性测试；同条件不全量重跑。无需正式打包、不加构建号。生产代码须保持不变；若必须生产改动先报告具体阻塞，不擅自修。
