# 歌词文字缓存 R2：失败处理与保真验证

沿用现有 OpenCode 会话、模型和分支。先读 AGENTS.md、`docs/reports/desktop-lyrics-swiftui-text-fidelity-r1-independent.md`。严格保留已通过的生命周期、时钟、seek 修复；仍为 debug-only 隔离原型，不接入生产。

## Codex 指定修法

1. 修复 `buildTextImages` 抓图失败只记录日志、可能保留旧图：准备底字和强调字时以原子方式提交整对图像；任一失败先清除当前旧图像、mask、旧几何及出栈资源，记录可测试的显式失败状态，不将失败标记成成功缓存，不静默退回另一后端。正常空行独立处理，不视为错误。提供可注入的抓图失败 seam：分别覆盖第一张和第二张失败、失败后恢复、stop 清理；不得通过真实资源耗尽触发。
2. 长句保真先修正验证方法，再决定是否能落地：使用一个统一参考 harness，同一屏幕实际 backing scale、颜色、尺寸、锚、时间轴、生产参考和新后端；在同一个稳定状态下比较，避免在切后端/切行过渡中采图。对 1.5、4、6.5 秒记录实际行选择、行尾、逻辑 offset、实际图层 position、contentsScale、位图尺寸、截图时是否有活动动画；保存原始图。以同一 harness 重现或解释上一批 1.96 与 17.739 均值之差。抓图失败/空图/写盘失败必须失败。
3. 定位先比较生产 SwiftUI 的文字布局、位图尺寸与裁剪坐标，随后检查分数位移采样和合成；不能根据墨迹框或单点数字推断根因。仅在有证据证明明确差异时做最小修正：保持原始 LyricsLineLayout 公式、30Hz、字形、字距和动画，不随意像素取整、不每帧生成图像。无法证明保真时记录并停止，不自行换架构、不接入生产。
4. 在可控的单个复用隔离画布上补 emoji 与换句关键帧的对照，1x 仅在真实 1x 可用时声称实测；否则明确写未验，不以 2x 重采样冒充。不得批量闪窗或控制真实播放。检查颜色、遮罩、裁切和入/出栈位置，不只比较动画计数。
5. 保持新后端同一句连续 30 帧无 rootView 更新、文字测量、位图生成；缓存只保留当前/出栈行。跑 R1 独立报告同组回归及新测试，失败/跳过/通过分开统计。无可比运行环境就报告 CPU 未验。

输出 `docs/reports/desktop-lyrics-swiftui-text-fidelity-r2.md`，保存对照原图、测试命令和未解决风险；无法达成视觉等价必须如实写明。禁止安装、启动/替换当前 App、真实播放操作、打包提交、改锁屏或波形。完成后停止等待 Codex 独立验收。
