# 锁屏“下移”根因取证（2026-11-03，Codex 直接）

用户提供 `3a4155c3a84637b2c3f7088996bd39dd.mp4`（20.833s，1280×720，30fps，HEVC），并明确“锁定和解锁两头都有”下移。
本文件只记录离线抽帧与既有实机日志的对照，不含真实锁屏操作。

## 抽帧观察

派生帧：`/private/tmp/valora-mp4-review/lock_001.png`–`lock_022.png`（4.6–6.8s，10fps）。

- t≈5.1s：桌面状态，物理刘海与顶边贴合。
- t≈5.3s（`lock_008`）：刘海面板仍是宽的收起过程，**顶边贴合**屏幕顶部。
- t≈5.4s（`lock_009`）：面板变窄并**整体下移约 55px（录屏像素）**，脱离物理刘海。
- t≈5.5s（`lock_010`）：下移到日期“10月29日周四”上方，宽度同步缩小。
- t≈6.5s（`lock_020`）：稳定锁屏态，面板**回到顶边并贴合**。

即：不是稳态错位，而是**锁屏/解锁过渡期间的一次缩放位移**，稳定后自行回到顶部。

## 与实机日志对照

`/private/tmp/valora-v0039-r1-live-20261103.jsonl`、`valora-v0039-r1-lock-handoff.jsonl` 中同一窗口：

| 阶段 | AppKit `panelAfter` | `serverBoundsQuartz` |
|---|---|---|
| hidden | `[552,797,624,320]` | `[552,0,624,320]` |
| locked | `[552,797,624,320]` | `[552,0,624,320]`（一次 `[554,5,620,318]`） |
| unlocking | `[552,797,624,320]` | `[583,55,562,289]` / `[576,44,576,295]` / `[573,37,582,300]` |
| restoring | `[552,797,624,320]` | `[552,0,624,320]` |

624→562 为 0.900，320→289 为 0.903；顶边下移 55 ≈ 1117×0.05。
即窗口 AppKit 几何全程不变，是 WindowServer 把该窗口当作**用户会话桌面表面的一部分**，随锁解过渡做 0.9 缩放并把顶边推下 5% 屏高。

## 结论

- 不是 SwiftUI 形状偏移、不是 `hostTop`、不是 y 补偿缺失。
- 触发条件是该窗口同时属于普通桌面 Space（实测成员 `[1, own]`）。仅 `[1]`（hidden 阶段）时 Quartz 恒为 `Y=0`，但会被登录界面遮挡。
- 因此正确方向是：锁屏期间只保留自建 level 400 Space 成员，不再同时属于桌面 Space。
