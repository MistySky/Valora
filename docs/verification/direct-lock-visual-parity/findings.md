# 锁屏视觉对齐取证（2026-11-03）

用户提供的两张实拍：`current-valora-lock.jpg`（Valora V0040 候选，V0039-R2 独占 Space 修复生效）、`original-alcove-lock.jpg`（原版 Alcove）。只对这两张图做离线测量，未再驱动真实锁屏。

## 1. 顶部刘海

当前截图里锁屏胶囊与物理刘海贴合，说明 V0039-R2 的独占 Space 修复在该包生效；未再发现旧的下浮。原版截图顶部被天花板灯反射过曝，无法可靠量取锁屏条几何，本条只作“当前已贴合”的记录，不做像素级对比。

## 2. 耳机信息：形态不同（已改）

- 原版：`icon + 100%` 单行，直接印在壁纸上，无底板、无设备名。
- 当前：约 360×94 的圆角毛玻璃卡片，24pt 图标 + 设备名「雨落纷飞的AirPods」+ `100%`（来自复刻的 `LockInformationView` tile 分支）。

## 3. 进度条未播放段（已改）

像素采样（灰度 0–255）：

| | 卡片底色 | 已播放 | 未播放轨道 |
|---|---|---|---|
| 当前 | ≈120–138 | ≈213–244 | ≈125–133（与卡片底色几乎相同，读不出来） |
| 原版 | ≈133–140 | ≈239–252 | ≈154–159（明显高于卡片底色） |

当前轨道 `.gray.opacity(0.25)` 压在灰色卡片上只相差约 +5…13，原版相差约 +20…22。

## 4. 卡片材质：`.hudWindow` 本来就接近，换材质反而更糟

第一轮只用“卡片上沿同一列（x=900）”比较，得出当前压暗 ≈42%、原版 ≈21%，据此把材质换成 `.underWindowBackground`。
用户在真机上锁屏后证明这是错的：新卡变成接近不透明深色。改按**整行平均**重新测量（灰阶 0–255）：

| | 卡片上沿外（同一行） | 卡片内部 | 比值 |
|---|---|---|---|
| `.underWindowBackground`（被否） | ≈205 | ≈60 | 0.29 |
| `.hudWindow`（原方案） | ≈205 | ≈120 | 0.59 |
| 原版 Alcove | ≈200 | ≈137 | 0.69 |

偏差主要来自两张照片曝光不同（原版整体更亮/更过曝），`.hudWindow` 与原版只差约一成，属于照片误差范围；`.underWindowBackground` 差了 2 倍以上。

结论：材质保持 `.hudWindow`，本轮回退该改动。单列采样容易被局部背景误导，后续跨照片比较必须用同行/多列平均。

## 边界

- 两张照片角度、距离、曝光不同，绝对值只能作方向性判断；跨照片比较一律用“同一列上沿 vs 内部”的比值，不做绝对坐标对齐。
- 未在本轮真实锁屏取新帧；改后观感仍须用户解锁一次确认。
- 图片为用户提供，仅作本项目对照证据，未用于其他用途。
