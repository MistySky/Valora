### 1.1 媒体断线恢复

`Controllers.swift` 的最小改动：

1. 增加窄接口 `SystemMediaProviding`，`SystemMediaSource` 原样 conform；生产默认仍注入真实 source，仅测试可注入 fake。
2. `onError` 现在同时置 `systemStarted = false`，并设置 `retryNotBefore = now + retryInterval`（生产默认 1.0 s）；随后 `clearMedia(error:)` 保持原行为。
3. 既有 1 s 定时 `refresh()` 在 `retryNotBefore` 之后才重新 `start()`；只在 `systemStarted == false` 时启动，因此同一时刻不会多开 adapter。
4. `stop()` 置 `isActive = false`，`refresh()` 首先检查 `isActive`；停止后即使被调用也不会重连。`invalidate()`（禁用/启用的既有路径）重置 `systemStarted`、`retryNotBefore` 和快照；禁用时 `refresh` 的 `nowPlayingEnabled` 检查保持原样。
5. 失败重试没有同步递归或紧密循环：仅由既有 0.25 s timer 的每 1 s refresh 驱动，并受 1 s backoff 限制。

测试（真实 `MediaController` + `FakeSystemMediaSource`）：

- 首次 `start()` 失败 → 下一次 `refresh()` 成功后模型标题/控制能力/错误状态恢复。
- 运行中流退出（fake `onError`）→ 清空状态 → 下一次 `refresh()` 恢复新快照。
- 失败后 100 次连续 `refresh()` 不会启动（backoff）；成功后 100 次连续 `refresh()` 仍只有 1 个启动；`doubleStarts == 0`。
- `stop()` 后 20 次 `refresh()` 不启动。
- 禁用 `nowPlayingEnabled` 后 20 次 `refresh()` 不启动。

### 1.2 seek 安全边界

旧代码 `Int64(target * 1_000_000)` 在 duration 为有限超大值或缩放超出 Int64 时会 trap。新增：

```swift
static func seekMicros(_ seconds: Double) -> Int64? {
    guard seconds.isFinite, seconds >= 0 else { return nil }
    let scaled = seconds * 1_000_000
    guard scaled.isFinite, scaled >= 0,
          scaled < 9_223_372_036_854_775_808.0 else { return nil }
    return Int64(scaled)
}
```

- 只有转换成功才构造 `["seek", micros]` 并调用 `system.perform`；拒绝时不调用 runner。
- 保留旧实现的截断（truncate）而非改为四舍五入；保留 `MediaProgressState.clamp` 对负值/超 duration 的既有语义。
- 预览模式、正常 seek、clamp 行为不变；真实播放器仍未收到任何测试命令。

回归覆盖：普通 74.5 s、`1.0000009 s` 截断、负值 clamp 到 0、`1e300` 被 clamp 后正常、`1e308/1e300` 不可表示拒绝、NaN/±Infinity 拒绝、`Double(Int64.max)/1e6` 边界拒绝、`Int64.max/2` 边界内的可表示值正常派发。
