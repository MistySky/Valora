# 桌面歌词实验接入 R2：外层对齐绑定实际显示行

执行：原会话、原模型、分支 `codex/idle-cpu-optimization`。按 `docs/opencode-tasks/desktop-lyrics-experiment-integration-r2.md` 修复。普通构建隔离与锁屏旧路径保留；未打包、未启动/替换 App、未提交。

## 一、问题与修复

**问题**：`ExperimentalDesktopLyricsView.isLong` 之前读取 `model.currentLyricLine`（基于慢采样 `model.elapsed`，收起态约 1Hz），而原生 renderer 按插值时间自行选行；边界换句后新文字已显示，外层 leading/center 仍可能滞后近一个采样周期。

**修复**：

- 原生行的换行回调改为携带完整 `LyricLine?`，经已有的 generation/identity 校验异步投递给宿主。
- 宿主 `LyricsRowExperimentHost.displayedLine` 保存**实际显示行**；外层 `isLong` 与无障碍文本都由它计算，不再读取 `model.currentLyricLine` 或旧 `elapsed`。
- 只在真实换行或宽度变化时重算 `LyricsLineMetrics`（宿主节奏）；30Hz 状态没有提升到 SwiftUI。
- 首次挂载、切歌、失败回退、空行与卸载：`begin`/`invalidate` 清理或换代；R1 的按身份/代次防护与整行回退保留。
- 时序说明（如实）：渲染器换行 → 异步回调（一个 runloop 跳）→ 宿主状态更新 → SwiftUI 在同一次显示周期内重排对齐；不再有 1Hz 采样滞后。未证明"零帧延迟/同一显示事务"的像素级时序，也不宣称。

## 二、真实宿主验证（实验构建，单一复用画布）

新增/更新的 `LyricsRowExperimentHostingTests`（真实 `NSHostingView`）：

| 用例 | 关键断言 |
|---|---|
| 恒定锚点跨短→长→短（带音符） | 不推送 `model.elapsed`；注入时间 1.2s / 5.2s 后，原生行与 `host.displayedLine` 同时为 1 / 5；长句出现后整行墨迹宽度变大 |
| 同上（无音符内嵌） | 行与宿主同步切换 |
| 宽度变化 | 同一行在"可容纳"与"溢出"两种宽度下，整行墨迹起点相差 >5px（center vs leading 实际渲染差异） |
| 切歌重试 | 身份 A 注入失败 → 回退；改标题/身份 → 失败清除并重新挂载原生行（旧身份失败不锁新歌） |
| 卸载迟到回调 | 移除视图后，用旧代次/身份投递行与失败回调均被忽略 |
| 失败回退 | 原生行被移除、capture 窗口计数回基线、回退整行与生产 **0.0%** 差异 |
| 短句/长句/内嵌整行对照 | 短句+音符 0.9%（mean 0.84）、长句+音符 8.7%（mean 1.57）、内嵌无音符 **0.0%**；外层尺寸相等 |

宿主状态测试（非渲染）：当前回调生效、旧代次/旧身份忽略、卸载后丢弃、失败/重置语义。
