## 1. 取消先于注册

`LyricsDeadlineRace` 增加一次性完成闩：

- `finished` 首次置位；若 continuation 尚未 attach，则保存 `pendingResult`；
- 后续 `attach` 发现已完成，直接 resume 保存的结果，不启动 provider/timeout waiter；
- 已 attach 时正常先 resume；再次 cancel/complete 不重复 resume；
- `@unchecked Sendable` 仅用于锁保护的状态，所有可变字段都在 `NSLock` 内；不持有 UI/model。
- 非结构化竞速仍保证 50ms/3s 预算不被不合作 provider 卡住；provider/timeout 均取消，迟到结果拒绝。
- 独立 `testImmediateCancellationDoesNotRetainController` 与 `testDeadlineSettlesWithoutWaitingForNoncooperativeProvider` 均通过；未删除 20ms owner 保活。

## 2. 真实采样锚

- `AppModel` 新增 `elapsedSampleDate` 与 `setElapsed(_:sampledAt:)`；`MediaController` 在每次计算 elapsed 的同一 `Date` 记录采样时刻。
- `CompactLyricsView` 不再用 `(model.elapsed, Date())` 建锚，而是调用 `model.lyricsElapsed(at:)`：
  - anchor = elapsed sample value + its sampled Date + playbackRate；
  - 延迟 0.20s 挂载显示 `elapsed + 0.20 * rate`；
  - 紧凑/展开/加载重挂载共享同一 model 采样锚，不把旧 elapsed 当作当前；
  - pause/rate<=0 不推进；seek 由新 elapsed 采样重置；播放恢复按实际。
- 增加 `testDelayedMountUsesElapsedSampleAge`，使用 AppModel 采样锚和延迟时刻，不是只构造两个 Clock 常量。
- 全局 elapsed 发布仍保持原 0.25s 频率，进度条/播放器底座未改。

## 3. 分段缓存安全

- `LyricMetricsCache` key 现包含：
  - 歌曲身份（title/artist/album/durationSeconds）；
  - 行 start/text；
  - 完整 word `(start,duration,text)` 分段。
- 同 text/start 从 1 word 变多个 word（或相反）会重建 width/prefix 数组。
- `currentWord`、fillWidth、readingOffset 均增加数组边界守卫；不依赖禁用歌词规避崩溃。
- 缓存仍最多 8 行/有界，30Hz 帧只查缓存，不重复测量整句；新增 `testSameTextAndStartButDifferentWordSegmentationRebuilds`。
