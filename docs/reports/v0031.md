## 2. Chrome 扩展

新增 `Resources/ChromeExtension/`（含 `BRIDGE-MANIFEST.json` 固定 extension/host/protocol/engine revision 关系），随包进入
`Contents/Resources/ChromeExtension`：

- MV3，仅 Chrome；名称/标题/按钮为 Valora。
- 权限仅 `contextMenus`、`downloads`、`nativeMessaging`、`notifications`；
  host permissions 仅为 `http://*/*`、`https://*/*`。
- 没有 `cookies`、`content_scripts`、`scripting`、`webRequest`、
  `<all_urls>`、媒体解析、YouTube/helper 或 Firefox/Edge 分支。
- 右键“使用 Valora 下载”只提交 HTTP(S) 链接。
- `downloads.onDeterminingFilename` 沿 Convoy 已确认的成熟拦截方式，
  但先向 Valora 查询桥接是否可用：
  - Valora 未运行/下载开关 off/host 未注册时，调用 `suggest()` 让
    Chrome 保留下载，并给出明确未启用提示；
  - 只有 Valora 接受后才取消并清除 Chrome 自己的下载记录；
  - 不发送 cookie、token、页面内容或浏览历史。
- popup 只查询实际 bridge 状态；host 不存在时不会伪装“已连接”，
  可显式打开 Valora。

## 3. Native host 与 IPC

新增 `ValoraNativeHost` 独立可执行目标：

- Chrome native messaging 使用 4 字节小端长度 + JSON；最大 1 MiB。
- 只通过本机 AF_UNIX socket `NSTemporaryDirectory()/valora-chrome-bridge.sock`
  与 Valora 通信，socket 以 `umask 077` 创建并 `chmod 0600`。
- 双方使用 sibling binary 的 designated requirement + audit token
  校验对端；未通过签名校验的进程不能取代 host/app。
- host→app 必须先发带有 `protocolVersion=1`、`app=Valora`、
  `hostName=com.wangqing.valora.chrome`、bundle ID 的 hello；app 也返回
  同样身份字段。旧 Convoy host/版本不会被识别为已就绪。
- 请求 schema 只接受 HTTP(S)、无 userinfo、有限长度 URL；拒绝
  `file:`, `data:`, `javascript:`, `ftp:`, 超大消息、超长文件名。
  host 不转发 cookies/token，app 只使用现有 `DownloadServicing.enqueue`。
- host 仅在用户显式发 `launchApp` 时打开 App；不会在每次下载时静默启动。
- 下载开关 off 时 App 不创建/关闭 bridge listener；重新开启才创建。
  `ChromeBridgeController.stop()` 关闭并删除 socket，递增请求代际，
  已接受的晚到请求不能继续写入。

## 4. Chrome 注册与诊断

新增 `ChromeBridgeRegistration`：

- 只写 Valora 专用文件
  `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.wangqing.valora.chrome.json`；
  不扫描、不枚举、不修改其他 browser/其他 App 的 host 文件，不提供
  Firefox/Edge 入口。
- 写入只在设置页明确点击“启用桥接/修复桥接”时发生；启动、刷新状态
  不写注册文件。
- 校验 host 的 canonical path 必须位于当前 `Valora.app/Contents/MacOS`，
  必须可执行、当前用户所有、group/world 不可写；临时 `/tmp` /
  `/private/tmp` / `NSTemporaryDirectory` 的 app 被拒绝，不能把 QA
  目录伪装成正式桥接。
- 状态仅从 Valora 自己的注册文件读取：`未设置` / `已设置` /
  `需要修复`。只有 manifest 匹配、host 有效且 bridge listener 正在运行时
  显示“已就绪”；Chrome 未运行只会显示“等待 Chrome 连接”，不会假报坏。
- 设置 → 下载保留原下载总开关，新增 Chrome 区：
  - 打开 `chrome://extensions`；
  - 打开随包扩展目录；
  - 开发者模式/加载已解压扩展步骤；
  - 本地桥接启用/修复及真实状态；
  - 明确仅支持 Google Chrome。

候选处于 `/private/tmp` 时，注册会被拒绝（正确行为）；用户需先把
`Valora.app` 放到稳定位置，再执行注册。

## 8. 用户最终安装步骤（本轮不代为执行）

1. 将候选 `Valora.app` 移到稳定位置（例如 `~/Applications` 或
   `/Applications`）；不要让正式注册指向 `/private/tmp`。
2. 打开 Google Chrome，访问 `chrome://extensions`，开启开发者模式。
3. 点击“加载已解压的扩展程序”，选择
   `Valora.app/Contents/Resources/ChromeExtension`。
4. 在 Valora → 设置 → 下载 → Chrome 扩展区点击“启用桥接/修复桥接”。
5. 保持下载总开关开启，测试普通 HTTP(S) 下载或右键“使用 Valora 下载”。
   下载开关关闭时 Chrome 会保留下载并提示未启用。
