## 1. 设备事件遇在途读取

### 根因

`ConnectivityController.refresh()` 在 `queryTask/queryInFlight` 存在时直接
return；`onConnect` 只调用 `known.remove` + `refresh`，因此连接事件在正在读取
时被丢弃。旧读取完成后可能把新连接标记消费掉，造成快速重连漏采。

### 修复

- 增加 `eventRevision` 与单槽 `pendingRefresh`。
- `onConnect`/输出事件先记录 revision，再设置 pending；普通 poll 在途不会
  人为再排队。
- 当前读取结束时：
  - 若事件 revision 已变化，**不应用这份旧快照**；
  - 若 `pendingRefresh` 存在，立即发起一次 fresh read，不等 3 秒 poll。
- 多个事件由单槽 pending/120ms notification debounce 合并，仍只有一个
  native read 在途。
- off/stop/setEnabled 递增 query generation、清 pending 和事件 revision；
  旧 generation 不能清除新 session 的 pending。
- 保留首次 baseline、不重复 arrival 动画、纯输出变化不当作新蓝牙连接。
- `ConnectivitySystemEvents` 的 onConnect 仍按 stable normalized id 移除
  known，production 与测试使用同一闭包路径。

- `testQueryIsBoundedToOneAndStaleResultIsIgnored` 仍保持 2 次读取、没有
  普通 poll 产生额外队列；

## 2、3. 音乐旧命令回调

### 根因

`commandGeneration` 只在新 `command` 时递增；`applySystem` 收到新权威
snapshot、`clearMedia`、`stop`、`invalidate`、源切换都没有失效旧
completion。旧失败 completion 因此可以：
- 把新歌曲的 playing 恢复为旧值并写入旧错误；
- 在 stop 后重新修改 model。

### 修复

- `applySystem` 检测新的权威状态（identity、playing、rate、duration）时
  递增 command generation；
- `stop`、`invalidate`、`clearMedia` 都递增 generation；
- completion guard generation，旧失败不再回滚/写错误；
- 保留播放/暂停即时可回滚反馈、真实后台命令、来源/能力校验、一次派发；
- 新权威 snapshot 到达后，旧 completion 不覆盖新状态；
- 未改 UI、封面、歌词、seek 或动画。

定向测试：

- `testFailedOldToggleCannotOverwriteNewTrackSnapshot` 通过；
- `testFailedToggleAfterStopCannotMutateModel` 通过；
- `MediaResponsiveness` 慢 source 即时反馈测试继续通过；
- 原有 11 项 MediaControllerRecovery 通过。
