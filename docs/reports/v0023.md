## 1. 根因

旧实现中：

- `SettingsView` 只在权限状态后续变化时清旧值，首次显示“未授权 + 已存 enabled=true + 无 pending”时没有纠正。
- `PermissionToggleRouting` getter 是 `value || pending`，把持久化旧值和当前授权/pending 混在一起。
- setter 开启时先 `guard !value`，旧值 true 会提前返回，吞掉用户点击。

因此出现“手形需要授权 + 设备开关 on”，且不先关一次无法发起授权。

## 2. 修复

### 2.1 路由语义

`PermissionToggleRouting` 现为：

- 显示为 on 仅当：
  - 有当前 pending 意图；或
  - 当前已授权且已存偏好为 on。
- 未授权的旧 on 值显示为 off，但不产生 setter 副作用。
- 用户点击开启时：
  - 已有 pending 不重复请求；
  - 已授权且已 on 保持；
  - 未授权则调用当前 `begin`，即使旧值仍为 true。
- 点击关闭仍先调用 `cancel` 再清偏好；pending/取消行为不变。

### 2.2 首次显示纠正

`SettingsView` 首次出现时执行只改本软件配置的 normalization：

- 蓝牙：无 pending 且不是 authorized、旧 `bluetoothEnabled` 为 true → 写 false；
- 日历：无 pending 且不是 fullAccess、旧 enableCalendar 为 true → 写 false；
- 登录项：无 pending 且不是 enabled、旧 launchAtLogin 为 true → 写 false。

只改 Valora 自己的偏好，不请求 TCC、不打开系统设置、不自动发起授权。已有授权、有效的 pending 意图不被清除。

`loginItem` 外部变化也改为：无当前 pending 时，任何非 enabled 状态清旧开启偏好；避免外部 grant 无意图时复活旧值。蓝牙/日历原有外部状态清除路径保留。

### 2.3 Controller gate

`ConnectivityController` 的授权 gate 未改：未授权后台 refresh 仍被拦截；本轮修复只让 UI/偏好与真实授权一致，不隐藏手、不伪造授权、不强开查询。
