## 2. 数据解析

- `rateLimitsByLimitId` 存在时以它为权威，包括空字典；只取全局 `codex` 桶，其他模型桶不会混入 5H/WEEK。
- 仅当该 map 缺失时才兼容旧 `rateLimits`。
- 5H 与 WEEK 按 `windowDurationMins` 300 / 10080 认；不接受其他长度冒充。
- usedPercent 缺失/非有限/越界保持 nil；真实 0/1 不被误判为 false，UI 显示“未提供”而不是零。 
- resetsAt 缺失/非正数保持未提供；过期不作假重置。
- reset `availableCount` 权威；credits 可缺/少于/多于可用数，按真实 expiresAt 排序，无到期日排在较后并明确“有效期未提供”；不推断补充时间，不执行使用。
- 同一返回统一更新三项；失败/缺引擎/未登录/超时/旧协议清空值并给明确状态，不把旧快照当实时成功。

## 3. Provider/生命周期

- `CodexUsageProvider`：单在途、合并打开刷新、generation 防旧结果、180 秒有限刷新、失败指数退避（上限 900 秒）、stop/取消清理。没有 1 秒网络轮询、历史库或无界缓存。
- `CodexAppServerClient`：启动 `codex app-server --listen stdio://` 后只为一次额度读取建立短进程；硬超时 10 秒（live probe 12 秒）、1 MiB stdout 上限、stderr 有界排空；defer 停止进程，取消/退出不遗留子进程。
- 每次 popover 打开只调用 `refreshOnOpen()`，不新建 provider/进程；关闭面板不新建进程；模块 sleep/stop/退出时 provider/timer/task 释放。
- 真实 live probe 只执行一次、只读：`status=ok`、约 2.44 秒、引擎找到、5H/周/重置数量字段均存在、重置卡明细 0 条；没有 account/read 或原始 RPC/账号字段落盘。
