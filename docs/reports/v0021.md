## 关键结论

1. **当前不能实现用户要求。** `SystemMediaSource` 只读取 macOS 当前 Now Playing；`MediaController` 只有一个 system 来源；适配器的 `send`/`seek` 没有目标应用参数。浏览器成为当前媒体时，Valora 显示和控制的就是浏览器。
2. **过滤浏览器无效**：只会隐藏/冻结当前系统流，不能读取后台音乐。
3. **缓存旧歌+本地计时无效**：不是真实来源更新，不能用于进度、暂停、seek 或歌词。
4. **不新增 Automation/Accessibility 的可用子集只有 system current**，无法满足“音乐不被网页抢占”和“显示/控制同源”。这不是 UI 文案能解决的问题。
5. 独立来源方案需要用户明确授权：
   - Apple Music / Spotify：Apple Events/Automation；
   - QQ：Accessibility/AX；
   - 私有 MediaRemote per-client：静态还原存在但无当前版本运行证据，风险最高，不建议第一版。

## 候选与推荐

- **A. system current**：保持现状；无新权限，但不满足优先。
- **B. app-specific adapters（推荐方向）**：复用 `AppModel`/UI/播放控制，新增薄的 `MediaSource` 协议和 `SourceCoordinator`；System fallback + Apple Music/QQ/Spotify adapter；权限按用户选择。
- **C. 私有 MediaRemote per-client**：归档/原版静态对象链存在（GetNowPlayingClients / GetNowPlayingInfoForClient / GetNowPlayingPlayerForClient / MRNowPlayingController sendCommand），但无当前运行证据、私有 ABI、历史 clientCount=0 限制；不先做。
- **D. 过滤/缓存**：拒绝。

### 推荐最小批次（需用户先决定）

建议先做“**显式用户选择来源**”的协调层，而不是自动应用排名：

1. `MediaSource` 协议 + `SourceCoordinator`，复用现有 `MediaController`/`AppModel`/UI；
2. 先接一个完整字段的 Apple Music adapter（本机有 sdef 和归档路径），system 作为 fallback；
3. 明确来源退出/暂停/无快照、权限 denied、取消/世代、歌词身份、进度锚、命令同源；
4. QQ 随后作为受限 adapter（无 seek/进度/封面）；Spotify 待安装/静态核验；网易云待证据；
5. 测试矩阵覆盖：浏览器接管、来源暂停/退出、快速切换、旧回调、命令前来源变化、歌词 identity、进度锚、权限 denied、多应用同时播放、现有音乐 UI 回归。

“不新增权限可做子集”只有 system current，不能作为优先功能的完成；如果用户不授权 Automation/AX，就不应实现/宣称 QQ/Apple Music/Spotify 独立优先。

## 需要用户决定

1. 允许的音乐来源范围（QQ/网易云/Apple Music/Spotify）与顺序。
2. 显式选择还是自动；自动时哪个优先，多个音乐同时播放如何处理；未决定前不排应用名次。
3. 浏览器/视频、网页音乐（如 YouTube Music）的归类。
4. 是否允许 Automation（Apple Music/Spotify）和 Accessibility（QQ）权限，以及首次使用是否弹窗。
5. 来源暂停/退出/不可用时清空、隐藏、回退还是保留（不得继续计时伪装更新）。
6. 是否允许在音乐设置增加最小来源选择控件。
7. QQ 无 duration/elapsed/artwork/seek 时 UI 的降级表现。
8. 是否安装 Spotify/网易云供后续静态/实机核验；未安装前不承诺。
9. 是否允许高风险私有 MediaRemote per-client 试验；不建议第一版。
