## 2. 设置整理

### 通用

`显示菜单栏图标` 现在是：

- 只有原文字 + 开关；
- 去掉 `menubar.rectangle` symbol；
- 去掉额外 info 说明及信息按钮。

侧栏图标和页面标题的 Alcove 图标保持不变。

### 下载

- 下载页保留原 `SettingsCard`、41pt 行、13pt 顶距/16pt 卡片间隔。
- 只保留下载总开关行；删除“再次开启只恢复列表和暂停状态…”的额外可见说明。
- 后台暂停/保存、再次开启不自动重新开始网络的语义未改。

### Chrome 区

默认只显示两行 41pt：

- `Chrome 扩展   待安装/不可用   安装…`
- `本地桥接     未设置/需修复/未监听/已设置/已就绪   启用/修复`

- 不再默认显示拼图装饰、HTTP(S)/注册文件/风控长说明。
- 只有用户点击“安装…”后，才显示一行短步骤与“打开扩展页 / 打开扩展目录”。
- 安装/注册失败只显示一条短句，例如“请先将 Valora 移到固定位置。”；
  技术原因写入 `os.Logger`，不在默认 UI 铺目录/实现细节。
- 真实状态仍来自 `ChromeBridgeRegistration`、bridge listener 与 handshake；
  不会因为 UI 精简而假报已连接。
- “待安装”只表示随包扩展可用/尚无 handshake，不声称 Chrome 已加载扩展。

## 4. 监控首次展开瞬态

### 源码证据（未打开真实 App）

1. `MenuBarModuleController.showCombinedPanel` 先构建
   `MonitorCodexCombinedView`，`present` 后才调用
   `monitor.setPanelVisible(true)`。
2. 首帧因此可能看到 `SystemMonitor.applicationState == .idle`；
   `MonitoringContentView` 的应用区是 36pt 的 loading 行。
3. `setPanelVisible(true)` 随后启动异步 tick，应用列表最多增长到 8 行；
   `NSHostingController` 使用 `.preferredContentSize`，外层 `ScrollView`
   加应用卡内层滚动可能在首次测量/布局期间出现临时指示器。
4. 这只是源码触发路径分析，**没有实际复现或视觉确认**。

### 最小修正

- `makeCombinedHost` 在展示前执行一次
  `host.view.layoutSubtreeIfNeeded()`，测量
  `host.view.fittingSize`；仅当测量高度小于 `maxHeight` 时预置
  `preferredContentSize`，不固定为错误高度。
- `MonitorCodexCombinedView` 在首次 monitor/Codex 为 `.idle/.loading` 时
  暂时使用 `.scrollIndicators(.hidden)`，数据就绪后恢复 `.automatic`；
  溢出内容仍可滚动，应用列表原有内层滚动、展开/搜索交互均保留。
- 没有永久隐藏滚动条、裁掉内容或删除应用列表滚动。

**视觉瞬态是否已消失仍待用户单次查看确认；本轮不声称视觉通过。**
