## 一、音符/文字居中：已修复并有宿主证据

### 原因

实验行把原生宿主固定为 `width: availableWidth`（撑满可用文字区），而生产 `CompactLyricsView` 对能放下的短句用**文字自身宽度**包裹，`音符 + 文字` 作为一个整体在行内居中；只有溢出长句才占满可用宽并靠前。

### 修复（`LyricsRowExperiment.swift` + `NativeLyricsRow.swift`）

- 渲染器在每次**准备文字**（换行/静态输入变化）时报告 SwiftUI 实际绘制的内容宽度（`onContentWidthChange`），宿主保存 `contentWidth`。
- 短句：内容区宽度 = 文字宽；长句：内容区宽 = `availableWidth`；空行报告 0 → 内容区收起，只剩音符居中（与生产空行一致）。
- 外框对齐仍由**实际显示行**的 `LyricsLineMetrics.totalWidth > availableWidth` 决定（leading/center），不读慢采样行、不把 30Hz 状态提升给 SwiftUI。
- 宽度变化只重排（复用已备图像），不重新抓图。

## 二、换句过渡：尝试 SwiftUI 化，未能在隔离宿主证明，已回退

按方案 2 尝试把换句呈现交给 SwiftUI（冻结旧行为静态图 + 新行为单一 live renderer，复用生产 `.offset(±26)+opacity` 与 `.easeInOut(0.2)`，关闭原生换句动画）：

- 真实宿主关键帧采集（0/50/100/150/200ms）：实验行从 0ms 起就是长句终态（ink 4857 恒定），没有过渡位移/透明度变化；生产参考为 742→964→4855→4857（有过渡）。
- 宿主状态/实例与时序处理未能让 SwiftUI 过渡在隔离宿主中真正播放（排查到 `beginSwitch` 的进入态未获得独立显示帧、以及注入时钟与逐行视图重建的交互），属于**未能保证正确**。
- 同时确认：原生 CA 换句在离屏窗口不可逐帧验证（CA 动画不推进），所以两套实现都无法在本 harness 得到“关键帧等价”的证据。
- 按任务第 3 条「不能保证正确就记录阻碍并停止，不擅自改参数/降帧/换效果」，**撤下 SwiftUI 过渡实现**，保留原有原生 CA 换句（0.2s easeInOut、±26pt、双向淡入淡出），避免实验版退化为无动画。代码中无过渡死路径。

**结论（如实）**：换句动画的“观感不如原版”**没有解决**；原因未定位到可安全修复的最小改动，需要真实 App 下的逐帧对照（本批禁止启动/替换）。不以计数或单张截图宣称体感等价。
