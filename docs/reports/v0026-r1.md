## 1. 修复的五个阻断项

### 1.1 stop / 隐藏 / 模块不可见不读取

- 日历模型初始化、`rebuild`、普通跨日只更新本地日期/网格，**不**调用事件 provider。
- 仅当：
  - 模型 `start`；
  - 面板实际打开；
  - calendar 模块可见；
  - `enableCalendar` 开启且 fullAccess gate 通过；
  才允许事件读取。
- 关闭面板、隐藏 calendar 模块、stop、失权/关开关立即失效并清可见事件；重开按最新 selectedDate 重新读取。
- 日期条的系统通知观察与面板事件查询分离。

### 1.2 最多一个实际在途、合并最新请求

- `MenuBarCalendarEventProviding` 为 injectable；测试使用 held continuation，而不是 sleep 猜取消。
- 事件模型有 `eventInFlight` 单在途 latch：快速切日只累计最新 requested day，不新建第二个 provider 调用；首个不合作 provider 完成后才启动最新请求。
- stop/失权后不启动下一请求；不因 Task.cancel 不生效而继续排队。
- provider 调用前再次校验 started/panelVisible/calendarModuleVisible/gate/generation/day；最终 commit guard 不替代调用前拦截。

### 1.3 今天跨月/跨年、时区

- 原本跟随今天的 selectedDate 跨日时，selectedDate、visibleMonth、网格一起迁到新月份；手动浏览其他月份不被强拉回。
- 时区通知使用注入 `timeZoneProvider` 更新实际 Calendar，再重算日界/网格/菜单栏日期；测试不修改系统时区。
- 日期加减使用 Foundation Calendar，没有固定 86400 秒。

### 1.4 菜单栏日期首次发布

- `UnifiedMenuBarController` 的 `$menuBarText` sink 现在使用发布的新值渲染 status date，不再从 willSet 旧属性读。
- 原生日期按钮在首次跨日测试中从 `3月1日 周一` 立即变为 `3月2日 周二`。

### 1.5 observer/controller 清理

- 默认 NotificationCenter tokens 和 NSWorkspace center tokens 分别保存/分别移除；队列回调检查 started/generation。
- `UnifiedMenuBarController.stop()` 清理 popover、subscriptions、close observer、Escape monitor、target/action；日历 panel visibility 置 false。
- stop/重复 start 不复活旧 popover 或旧事件回调。

## 2. 原生容器与可读性

- `popover.contentSize` 不再硬编码 300：按统一 view 的实际宽度/高度设置，至少 360 宽；高度以屏内可用高度为上界。
- 统一 view 使用垂直 ScrollView；7 列、农历副行、日期详情和事件多时不会被固定高度裁断；实际 `NSPopover` 的 contentSize 在 native action test 中核验宽度 >=360、高度 >100。
- 今日农历副行改为红色可读文字（不再红底外白字）。
- 仍保留 Calmon 风格月历（周一开头、年月标题、导航、今天、周标题、7列/4–6周、选中/周末/邻月/农历详情）；未新增格式选择器、全局快捷键或大型 CalendarPanelView。
- 本批不把设置/刘海改成玻璃材质；报告提出后续可单独确认局部原生 popover 材质方案，本次不擅自扩大 UI 改动。

## 3. 日历/日程功能

- 月历基础功能无需授权：今天/选中/周末/邻月、上月/下年、上/下月/年、回到今天、日期详情、农历；4/5/6 周自适应。
- 菜单栏日期采用 Calmon 默认 `M月d日 周X`；Calmon commit `72235116e1420fa081e8f694991a32809f81498d`，默认 `showWeekday=true`、周一开头、`showLunar=true`；未使用其整包依赖/资源。

- 本批未读取用户真实事件，所有日程 QA/preview 为明确 fake；无真实 EventKit 授权操作。
