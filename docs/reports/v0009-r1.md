# V0009-R1 交付报告：暂停空闲期限不再被换屏取消

- 任务：`docs/pi-tasks/v0009-r1-idle-deadline.md`
  （SHA256：`262af877338e83496922e05762ab6a87724b1036341690f971a0bc284156266f`，已核对）
- 依据：`docs/verification/independent-v0009/decision.md` 与 `idle-test.log`
- 结论：独立验收新增的 `testPausedIdleDeadlineSurvivesDisplaySelectionChange` 已从失败转为通过；显示选择/屏幕几何变化现在保留暂停空闲期限的剩余时间，不再留下永久 `pending=true` 的共享媒体计时。未改功能、未恢复定时派工。

## 1. 缺陷与定位

独立回归场景：

1. fake 歌曲暂停，`MediaIdleState.pending=true`；
2. 将显示选择从 “All displays” 切到 “Main display”；
3. `WindowCoordinator.place()` 调用 `PresentationController.resetForScreenChange()`；
4. 旧实现取消 `idleTask`，但保留 `mediaIdle.input` 和 `pending`；
5. 相同媒体输入再次走 `mediaStateChanged()` 时 `update()` 返回 `false`，没有重建任务；
6. 3.6 秒后活动仍 `visible=true`、`pending=true`。

根因是呈现层重置取消了共享媒体空闲计时，却没有保持剩余期限或重新建立有效计时。

## 2. 最小修复

只修改 `Sources/Valora/PresentationController.swift`：

- 新增 `idleDeadline: Date?`；每次安排暂停空闲任务时记录截止时间。
- `resetForScreenChange()` 在取消旧任务前计算剩余期限；仅当 `mediaIdle.pending` 为真时，用原 generation 和剩余期限重新安排任务。
- 截止时间已过时按 0 剩余立即完成；没有可用截止时间时才使用该输入的完整时长作为合理有效计时。
- `mediaStateChanged()` 对相同输入仍返回不更新，但若发现 `pending` 且没有运行中的 `idleTask`，会补建一次任务；已有任务时**不**因同值 metadata 轮询而延后。
- 成功过期后清空 `idleDeadline`；正常播放/暂停输入变化会先取消旧任务再按新状态安排。
- 未重写 `WindowCoordinator`、展开/收起动画、多屏所有权或媒体控制器。

### 同类取消路径核对

- **显示选择/几何变化**：`WindowCoordinator.place()` → `resetForScreenChange()`，现在保留剩余期限；独立回归覆盖。
- **屏幕拔插/参数变化**：同样走 `place()` 与 `resetForScreenChange()`。
- **全屏/调度中心隐藏**：`applyScreenState()` 在隐藏转换时调用同一 reset；剩余期限继续计时，不会永久中断。
- **禁用再启用**：禁用时 `mediaStateChanged()` 先将输入置为 disabled、`pending=false`，reset 不再留下计时；重新启用时新输入会建立新的有界任务。
- **同值 metadata 轮询**：已有 `idleTask` 时 `mediaStateChanged()` 直接返回，不移动截止时间；仅在任务确实不存在时补建。
