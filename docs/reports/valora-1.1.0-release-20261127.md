# Valora 1.1.0 发布验收

发布分支为 `codex/performance-preserve-motion`，继承 1.0.9 的 `7388098`。本版包含歌词时间校准与耳机连接电量修复。目标平台为 Apple Silicon、macOS 27.0 或更高版本。

## 歌词

同一首歌收到新的系统播放条目标识时，歌词宿主继续显示当前行。歌词时钟会等待后续独立报告，确认孤立的整秒偏差是否需要校正。进度条使用原有的播放时钟，用户主动拖动、切歌和自然循环仍可立即定位。未增加计时器。

此前用同一组匿名时间点分别按紧凑和展开的发布节奏回放，每种节奏采样 10,738 个渲染时刻。曾导致高亮停住一秒的事件在修复后能连续进入下一行。两次正常循环均回到开头，回放中未见非循环倒退。真实人声同步取决于播放器上报的时间和歌词版本。外部播放器内极小的回拖，若与孤立的整秒偏差无法区分，要等新的播放报告才能识别。

## 连接电量

原先入耳式 AirPods 的左右耳字段缺失时，会回退到整机字段。该字段的占位零值会把刘海电量环误染成红色。现在等待有效的耳机读数，同一条连接提示收到读数后就地更新。此判断也覆盖系统已经识别为 AirPods、具体型号稍后才到的情况。AirPods Max 使用整机电量。左右耳报告的实际 0% 仍有效。沿用既有的设备事件、采样频率和连接动画。

使用合成快照复现了旧版误报，并验证了占位零值、型号晚到、真实低电、中途补齐读数及连接动画触发次数。一次实际重连在首笔就拿到了左右耳读数，当次显示正常；首次连接误红的回归由模拟快照验证。[电量测试](../../Tests/ValoraTests/DeviceBatterySelectionTests.swift) · [连接流程测试](../../Tests/ValoraTests/ConnectivityControllerTests.swift)

## 发布回归

最终代码启用 `VALORA_LYRICS_EXPERIMENT=1`，共通过 182 项定向回归，其中应用测试 142 项、核心逻辑测试 40 项。范围包括歌词时钟、进度拖动、换句、刘海轮廓、封面、悬停、锁屏歌曲切换、设备连接、低电提醒和发布版启动参数。打包入口与构建号分配器的隔离检查均通过。

发布包构建号为 **86**。DMG 通过镜像完整性校验。只读挂载后核对了版本、最低系统、arm64 架构、主程序与媒体框架的哈希，以及 Applications 安装链接。应用和框架均通过严格深度验签，签名身份为 `Valora Self-Signed`，未经过 Apple 公证。五个开发启动参数均按预期返回退出码 2。
