## 1. Root causes fixed

### 1.1 Fresh nested persistence parent

`DownloadListLock` previously called `open()` before the persistence parent existed and
treated every non-`EWOULDBLOCK` result as ownership. A fresh nested root could therefore
produce a manager with `ownsDownloadList == true` while another manager also acquired
the same lock.

`DownloadListLock` now:

- creates the persistence parent directory **before** opening the lock;
- has explicit `.owned`, `.heldElsewhere` and `.unavailable` states;
- treats `open()` failure or any `flock` error other than `EWOULDBLOCK` as
  `.unavailable`, never as owned;
- closes the descriptor on denial/unavailability;
- exposes `isOwned` and an explicit unavailable reason.

`DownloadManager` creates the persistence parent before constructing the lock and uses
`listLock.isOwned` for `ownsDownloadList` — not `!isHeldElsewhere`.

### 1.2 Lock-denied cleanup deleted the owner's partial files

A lock-denied manager loaded no tasks. `clearOrphanedTemporaryFiles()` then built an
empty known-ID set and treated the owner's segments as orphans.

The blocked manager now:

- does not load persistence, create scratch or measure temporary storage;
- refuses `addDownload`/`addDownloads`/stream/YouTube creation and start/resume/retry;
- returns without cleanup/delete/cancel/remove mutations;
- `clearOrphanedTemporaryFiles()` returns `0` without scanning when it does not own
  storage or the list is unreadable;
- `refreshOrphanedTemporaryBytes()` and launch measurement are owner-only;
- exposes `downloadListUnavailableReason` for an explicit future UI/state; new
  downloads fail with `DownloadError.storageUnavailable`.

The owner's normal add/start/pause/resume/complete/save/cleanup paths remain ordinary
single-owner behavior. Persistence saving is still guarded by ownership and
`listIsUnreadable`.

No download algorithm, segment layout, pause/resume, merge, conflict, retry or UI
behavior was redesigned. No UI was changed.

- real local Range HTTP server and 20 MiB self-generated source;

  surviving segment scratch;

This supplements R1's completed-record recovery, which did not cover an unfinished
download.

uses a persistence parent that is a regular file, so directory/lock acquisition is
unavailable. It asserts `ownsDownloadList == false`, an unavailable reason, no scratch
directory, and a rejected add without a task or destination file.
