### 搜索与匹配

搜索端点：`https://c.y.qq.com/soso/fcgi-bin/client_search_cp?format=json&new_json=1&n=10&p=1&w=...`

- 两次请求均 HTTP **200**，各 10 条候选；当前响应是普通 JSON（不是旧 JSONP；解析器同时兼容 JSONP）。
- studio 选中 `songmid=0039MnYb0qxYhV`、数字 ID `97773`、专辑 `叶惠美`、269s。
- live 选中 `songmid=004Fs2FP1EvZYc`、数字 ID `244115385`、现场专辑、249s。
- 搜索候选中有同名 Live、DJ、KTV 伴奏、片段、其他歌手版本；匹配器要求歌名、版本标记、歌手、专辑和时长一致，未盲选第一首。
- 当前严格规则：请求专辑非空时，候选必须有相同专辑；空专辑不当作匹配证据。若仍有多条同等候选，返回 `ambiguous`，不取第一条。

### 逐行歌词

端点：`https://c.y.qq.com/lyric/fcgi-bin/fcg_query_lyric_new.fcg?songmid=...&g_tk=5381&format=json&nobase64=1`
（请求带 `Referer: https://y.qq.com/portal/player.html`）

- 两次均 HTTP **200**，`retcode=0`、`code=0`；本批保存的是结构摘要，不保存整首歌词。
- studio：`timed_lrc`，**63** 行带有效时间戳，首 0s，末 262.86s。
- live：`timed_lrc`，**36** 行，首 0s，末 239.43s。
- 两个响应均未携带 translation；报告不把“无翻译”外推为所有歌曲无翻译。
- `nobase64=1` 返回明文 LRC；解析器也支持响应中的 base64 payload。

### 逐字 QRC

端点：`https://c.y.qq.com/qqmusic/fcgi-bin/lyric_download.fcg`（POST，数字 songID）

- 两次均 HTTP **200**、`<result>0</result>`。
- 有 `<content>`：studio 9808 个字符、live 6784 个字符，均为 HEX 形态。
- **未解码**，因此没有取得任何实际逐字时间字段；探针明确写出 `decoded=false`、`decryption=not_implemented`。
- 没有用逐行 LRC 平均切字冒充逐字，也没有把 QRC 声明为已支持。解密与逐字时间核对留给独立后续小任务，见 `docs/verification/v0010/qrc-next-step.md`。

### 失败路径

- HTTP 非 200、无响应、JSON 解析失败、搜索 API code 非 0、歌词无 payload、匹配拒绝均会写入可定位的摘要，不把空响应写成成功。
- 请求不记录 cookie/token/身份标识；不重试、不无限尝试。
- 真实网络只手动运行；普通 `swift test` 不访问在线服务。

## 2. 实现

### ReferenceCore 新增

`Sources/ReferenceCore/QQMusicLyrics.swift`：

- `QQMusicSample`、`QQMusicCandidate`、`QQMusicMatchResult`。
- `QQMusicMatcher`：歌名规范化、括号版本标记（Live/Remix/伴奏/片段等）、歌手、专辑、时长容差；不确定返回 `noMatch`/`ambiguous`。
- `QQMusicSearchParser`：当前 JSON 与旧 JSONP 兼容，读取 `mid`/`songmid`、`id`/`songid`、`title`/`songname`、`album.name`、`singer`、`interval`。
- `QQMusicLyricResponse`：读取 `retcode`/`code`/`subcode`，支持明文和 base64 payload。
- `LRCParser`：元数据、offset、多个时间戳、无效时间边界、行顺序；区分 timed/plainText/instrumental/empty。
- `QRCParser`：仅解析标准 QRC 文本形态的 `[lineStart,lineDuration]word(start,duration)`，有离线合成测试；**不声称真实 QRC 已解密或接入**。

解析/匹配为独立 Swift 实现，没有复制参考仓库源码，没有新增第三方包。

### 探针

- `scripts/qq_lyrics_probe.swift`：独立 `@main` Swift 6/Foundation `URLSession` 程序，只读取显式样例文件，输出目录必须显式给出。
- `scripts/run_qq_lyrics_probe.sh`：把纯解析核心与探针一起编译到临时目录，不启动/链接 Valora App。
- `scripts/qq_lyrics_sample.json`：显式公开样例。
- 探针未接入 App 启动、设置、播放器、NotchView、QuickPeek 或状态栏菜单。

参考来源与许可详见 `docs/verification/v0010/source-license.md`：LyricsKit 为 MPL-2.0 协议参考，Lyrimuse 为 GPL-3.0 仅作协议观察；没有复制/链接 GPL 或 MPL 源码，也没有引入 Go 引擎或 QQ 本地曲库读取。
