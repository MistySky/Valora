## 1. 修复

### 门控顺序

- **搜索**：HTTP 2xx → 必需 `code=0` → 必需 `data.song.list` 结构 → 才解析候选/匹配。
- **逐行歌词**：HTTP 2xx → 必需 `retcode=0` 且 `code=0` → 才解析 payload；HTTP/API 失败不会落入 `no_lyrics` 或 `timed_lrc`。
- **QRC**：HTTP 2xx → 必需 `<result>`；`result=-1` 表示无内容（有效业务结果），其他非 0 为业务失败；`result=0` 必须有 `<content>`。内容仍加密，未解码。
- **退出码**：探针仅在无请求失败、无 QRC 请求失败时返回 0；`request_failures`/`qrc_failures` 会返回非 0。`no_lyrics` 与 `no_match` 保留为不同状态，不伪装成成功歌词或网络失败。

### 代码变化

- `Sources/ReferenceCore/QQMusicLyrics.swift`
  - 新增 `QQMusicResponseFailure`、`QQMusicSearchEvaluator`、`QQMusicLyricEvaluator`、`QQMusicQRCEvaluator`。
  - 搜索/歌词响应要求关键字段存在；缺失或无效结构明确失败。
  - QRC evaluator 只验证结果/内容形态，不解密、不产生时间戳。
- `scripts/qq_lyrics_probe.swift`
  - 搜索/LRC/QRC 均先走 evaluator。
  - 每个样例输出 `request_ok`、`status`、错误诊断；顶层输出 `request_ok`、`validation_ok`、`request_failures`、`qrc_failures`、`statuses`。
  - `fetchLyrics` 保持可被外部离线模拟调用的接口；`@main` 仅在显式编译标志下启用。
- `scripts/run_qq_lyrics_probe.sh`：Swift 6 + 显式 `QQ_LYRICS_PROBE_MAIN` 编译标志。

未修改 AppDelegate、NotchView、设置页、播放器、图标资源、打包接线；QRC 解析器本批未接入或用于 UI。

## 2. 离线回归

- HTTP 503 + 看似有效的 LRC body → `httpStatus(503)`，不是 `timedLRC`。
