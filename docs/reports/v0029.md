## 2. 公开 API 与自动副作用

详见 `docs/verification/v0029/api-audit.md`。要点：

- **DownloadManager**：`shared` + private init；初始化即获取固定 Application Support/Convoy lock、读取/解码 `downloads.json`、测量系统 temp、订阅 `AppSettings.shared`；没有公开注入路径。
- **DownloadTask**：公开只读状态/进度/segmentMap、公开 `init` 可用于纯 fixture；实际 start/pause/resume/cancel 由 manager 驱动。
- **SegmentMap**：公开只读布局与 spans；`DownloadSegment` 是内部 actor。
- **AppSettings**：`shared` + private init，全部 `@AppStorage` `.standard`，初始化会补 Downloads 默认路径；无注入 defaults。
- **TemporaryStorage**：public report/remove 允许传入 container，但这是独立工具，manager 的任务临时文件和 persistence 不接收该 root。
- **删除**：`DeletionPlan`/`delete(taskIDs:moveFilesToTrash:)` 区分完成文件 Trash 和未完成临时进度；真实操作未执行。

## 3. 隔离判定

阻断完整运行：

- 不能安全构造 manager（private init/only shared）；
- 持久化/锁路径硬编码 `Application Support/Convoy`；
- settings 是 `.standard` 单例，无法指向 Valora suite；
- 任务临时文件 root 硬编码系统 temp；
- 用 `HOME`/全局 UserDefaults/外部 sandbox 进程绕过都被视为不可维护且未采用。

因此**未实例化 `DownloadManager.shared`，未触碰用户 Convoy downloads、Downloads 或个人目录，未运行真实 HTTP Range fixture**。这不宣称下载完整接入。

`docs/verification/v0029/proposed-isolation.patch` 是上游最小隔离补丁草案，不是已应用补丁，也不修改 `.build/checkouts`：

- 注入 persistenceURL/scratchContainer/defaults；
- 显式 factory 延迟 launch measurement；
- 由 Valora 使用自己的 Application Support/Caches/UserDefaults 根。

需要 Codex/用户决定是否接受该 upstream 修改或另立 fork 方案；当前没有擅自 fork/推送。

## 4. 自有边界

新增 `Sources/Valora/DownloadEngineAdapter.swift`：

- `DownloadItemSnapshot` / `DownloadSegmentSnapshot` 不可变 Sendable 值；
- `DownloadServicing` 接口（items/enqueue/pause/resume/cancel）；
- `DownloadEngineCompatibility`：纯 status/segment/task 映射，`isLinked` 仅读取纯常量；
