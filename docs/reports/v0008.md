## 1. 精简附加控制

### 原因

用户实测原版 Alcove 也无法控制当前 QQ 的随机/循环，决定不再保留无实际价值的附加控制。标题标记此前已按用户补充要求整组删除。

### 删除的专用链路

- 设置页整个 Favorite/Shuffle/Repeat/Copy 组及其尾部分隔线
- `SettingsView` 的 `controlChoiceBinding`
- `RevivalSettings.controlChoice` 读取/保存/sanitize
- `MusicPlayerContent` 的额外模式按钮（`extraControl`）
- `AppModel.shuffleMode`/`repeatMode`
- `MediaController` 的 shuffle/repeat 快照字段、清理和 `send 6/7` 入口
- `SystemMediaSnapshot` 的 `shuffleMode`/`repeatMode` 解析
- `MediaControllerRecoveryTests` 的 shuffle/repeat fake 测试
- `SystemMediaSnapshotTests` 的模式测试
- `SettingsReductionTests` 的 controlChoice/额外控制断言
- `SettingsVerification` 的 Repeat 选中截图与 controlChoice 修改
- `SettingsControls` 的 Favorite 预览循环及对应本地化标签

旧 `controlChoice` 偏好键不读取、不清空；用户其它已支持设置值不受影响。未修改 vendor MediaRemote 源码或公共框架。

### 最终可见设置

**通用**：登录时启动、强制模拟刘海、显示于、悬停时展开；仅开启悬停时显示悬停延迟滑块。

**正在播放**：正在播放总开关、进度条样式、使用实时波形。

标题标记与附加控制均已移除，无空卡片、灰色占位或多余分隔线。

## 2. 右击刘海打开设置

实现：

- `NotchView` 外层形状及展开内容共享 `settingsMenuItem`：`Button("设置…") { model.showSettingsAction?() }`；使用 SwiftUI `.contextMenu`，没有新增全局鼠标拦截。
- `AppDelegate` 注入 `model.showSettingsAction = { [weak self] in self?.showSettings() }`，复用既有 `settingsWindow` 与 `SettingsWindowFactory`。
- 右键菜单作用于当前可见形状；面板外层 `ignoresMouseEvents`/轮廓命中逻辑未改，刘海外仍点透；左键播放/进度/音量/悬停逻辑未改。

验证：

- 真实紧凑刘海：CGEvent 右击后菜单显示“设置…”，截图 `docs/verification/v0008/context-menu-compact.png`（仅菜单条区域，无歌曲文字/封面）。
- 点击“设置…”后实际打开已有“通用”窗口（620×687）；再次右键/点击后 `NSWindow` 数量仍为 1，窗口号复用（`context-menu-verification.json`）。
- `SettingsReductionTests.testExistingSettingsWindowIsReused` 通过。
- 展开态使用同一 shared `settingsMenuItem`（外层与 expanded content 均有 `.contextMenu`）；自动化合成右击在非激活面板上的展开态未能可靠复现，未伪称实屏通过，留给用户/Codex 实机复核。紧凑态已实际验证。
