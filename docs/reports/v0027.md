## 1. 迁移方式

Calmon 的菜单栏日历/监控源码直接作为底稿，保留成熟布局、字体、材质和计算口径。具体映射见 `docs/verification/v0027/source-mapping.md`：

| 领域 | Calmon 源 | Valora 落点 |
|---|---|---|
| 菜单栏路由 | `CalMon/App/MenuBarController.swift` | `MenuBarModuleController.swift` |
| UI 常量 | `CalMon/App/UIStyle.swift` | `CalmonMenuBarStyle.swift` |
| 日历模型/视图/组件 | `CalMon/Calendar/{CalendarModel,CalendarView,CalendarComponents}.swift` | `CalmonCalendarModel/View.swift`、`MenuBarCalendarComponents.swift` |
| 节气/农历底座 | `CalMon/Calendar/HolidayProvider.swift` | `CalmonHolidayProvider.swift`（仅节气资源与显示类型） |
| 系统监控 | `CalMon/Monitoring/{SystemMonitor,AppMemoryReader,MonitoringView}.swift` | 同名 Valora 文件 |
| 搜索输入控件 | `CalMon/App/InsetTextFieldCell.swift` | `InsetTextFieldCell.swift` |
| 节气数据 | `CalMon/Resources/SolarTerms/*.json` | `Sources/Valora/Resources/SolarTerms/*.json`，打包到应用 `Resources/SolarTerms` |

没有迁入 Calmon 全局快捷键、大日历面板、主题选择、设置窗口、应用图标、登录项、历史测试/个人数据或自动更新。

## 2. 各自独立的状态项与弹窗

生产菜单栏现在是：

- **系统监控**：独立 `NSStatusItem`，两行固定宽度 CPU/MEM；左击独立 `NSPopover`；右击仅 `版本`（禁用）→`设置…`→分隔线→`退出 Valora`。
- **日历**：独立 `NSStatusItem`，Calmon `13 pt monospacedDigit` 日期；左击独立 `NSPopover`；右击同一套基础菜单。
- **Outline-v7 软件图标**：由 AppDelegate 独立创建并始终存在，不是“所有模块关闭才显示”的 fallback。它保留原有左右键和音乐管理菜单（播放/暂停、上一首、下一首、显示器、版本、设置、退出），不打开模块弹窗。
- 两个模块入口初始创建顺序按 Calmon 的“后建在左”规则为 **系统监控 → 日历**；不强制锁定用户的系统重排。AI 用量没有状态项。
- 同一时间只开一个模块弹窗；打开另一个会关闭当前；重复左击关闭；右击不打开模块弹窗。
- 仍复用同一个模块 `NSPopover` 实例，关闭时释放 SwiftUI content view tree；状态项在 stop/隐藏时移除，应用图标不受影响。
- 刘海右键、歌词、音乐、设备、锁屏、多屏和标题双击代码未接入本批菜单栏路由。

验证记录：`native/verification.json` 的 `independentStatusItems`、`identitiesDistinct`、`calendarPanelShown`、`monitorPanelShown`、`calendarClosed`、`monitorClosed`；基础菜单标题为 `版本 0.1.0`、`设置…`、`""`、`退出 Valora`，无播放/切歌/显示器。

## 3. 日历

- 保留 Calmon 小月历布局：360 pt 面板、7 列、周一开头、年月标题、双箭头前/后年与单箭头前/后月、今天、周末红色、选中/今天圆角色块、农历副行、节气点和日期详情。
- 月历/日期基础浏览不依赖日历授权；7 列完整；popover 内容尺寸随内容且以屏幕可用高度上限，内部垂直滚动。
- 农历与 2025–2027 节气数据迁入；`HolidayProvider` 不再包含 Calmon 的 EventKit 节假日来源自动发现/授权/自动范围读取，避免隐藏读取。
- 系统日程使用现有 Alcove 风格 `CalendarAuthorization`/`AppPermissions`/设置单开关：
  - `enableCalendar` 仍只是事件读取同意，不作为模块显隐开关；
  - 只有面板实际可见、calendar 模块可见、已有授权 pragma 且 `fullAccess` 时才调用只读 adapter；
  - 关闭面板/隐藏模块/stop/失权立即失效并清空可见事件；快速切日最多一个实际在途并合并最新日；不合作 provider 不会被第二条查询叠加；
  - 未授权/拒绝时基础月历仍可浏览并显示授权提示。
- Calmon 原有节假日标记未伪造；系统 event 只显示选中日本地日界的标题/时间/全天状态，不读取备注、地点、参与者、账号或其他日程内容。
- 本批 QA 使用明确 `PreviewCalendarEvents` 样例；`native/verification.json` 标记 `calendarSampleOnly: true`、`eventKitQueried: false`，所有证据均不是个人日程。

## 4. 系统监控

- 直接使用 Calmon `SystemMonitor` / `AppMemoryReader` 的公开 Mach/libproc/NSWorkspace 读取与计算：
  - 3 秒 CPU/MEM 菜单栏采样；面板打开才读取应用列表和磁盘，面板关闭清空应用列表/磁盘；
  - 应用列表默认 8 行、查看更多、搜索；应用归并到顶层 `.app`，使用 `ri_phys_footprint`；
  - CPU/MEM/磁盘概览、圆环、使用/未使用、内存/磁盘单位格式沿用 Calmon；
  - 单采样在途；关闭面板的旧回调被 generation 丢弃并 trim 图标缓存；打开面板排队一次立即采样；
  - sleep 关闭弹窗并停止监控定时器，wake 重建 CPU 基线；模块隐藏停止全部监控；退出移除状态项和 timer。
- 不新增温度、风扇、网络历史、GPU、磁盘读写速度或后台长期记录；不读文件、账号内容、设备/权限。
- 本机有界公开读取由 `SystemMonitorTests.testLiveReadsReturnPlausiblePublicValues` 验证（单次 CPU/memory/disk 资源值，不长期留存）。验证器截图使用注入固定 snapshot，明确标为 `预览样例 · 注入系统/应用数据`。
