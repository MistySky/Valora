## 1. 封面翻转

### 1.1 现状与关键路径

生产路径仍是：

- `Sources/Valora/TransitioningArtwork.swift`
  - `ArtworkTransitionController.placeholderIdentity`
  - `update(image:identity:animated:)`
  - `runTransition()` / `stop()`
- `Sources/ReferenceCore/ArtworkTransitionState.swift`
  - `set` / `finishOutgoing` / `finishIncoming`
  - `ArtworkFlipMetrics`：outgoing 0.15s，incoming 0.275s，bounce 0.375，effect 0.55s + delay 0.05s。
- `Sources/Valora/NotchView.swift` 的 `TransitioningArtwork`：`scaleEffect(x:y:1)`、incoming `brightness`、outgoing/incoming `blur`，以及 Reduce Motion 分支。

交接的占位逻辑是：

- 新歌元数据先到、封面为空时，如果已有 `state.current`，把 `placeholderIdentity` 作为新的 current；因为缺失帧传入 `animated && !missing`，这一步是**立即**清掉旧图，不会把旧图作为新歌继续显示。
- 晚到封面时，current 已经是占位身份，因此 `update` 会走 `outgoing -> incoming`，而不是当成“首次挂载直接出图”。
- 旧封面不会重新出现；占位以深色音符卡（`Artwork` 的 nil 分支）参与收窄，然后新图展开。

### 1.2 视频对照

实际查看记录与限制见 `docs/verification/v0018/video-comparison.md`：

- `cover-10fps-contact.png`：0.0–9.9秒，0.1秒间隔；实际看到多次横向收窄、竖线、模糊/亮化展开。
- `transition-60fps/`：1.800–2.583秒共44张裁剪帧；按 `transition-frame-times.json` 的真实采样时间，不把目录名的“60fps”当成严格等间隔。
- 约2.0–2.05秒旧图到近竖线；约2.083–2.183秒新图模糊、亮度提高并展开；约2.2–2.5秒回稳并清晰。
- 未把录屏聊天/桌面背景复制或上传；后半段 QQ 窗口只在本地查看，不作为双击成功证据。

### 1.3 实际 SwiftUI 视图阶段，而非只看 state

- 覆盖直接 A→B；另测“旧图→nil→晚到 B”在实际视图仍出现动画，且 gap 本身不保留旧封面的动画。
- 证据阶段图用实际视图的 `CALayer.presentation().render(in:)` 取得，不是仅缓存最终状态（但仍存在离屏渲染限制，见下）。

### 1.4 覆盖的回归

`ArtworkGapTransitionTests` 现为 6 项（本轮新增 3 项）：

- 晚到封面仍进入 outgoing/incoming；
- 直接 A→B 的两阶段与最终 current；
- 同图/同 identity 不重启；
- stop/失败不复活旧图；
- 连续快速切歌最终只保留最新；
- disabled / 首图立即显示。

新增的实际视图测试 2 项；实际 hosting layer 与 gap 动画均通过。

### 1.5 占位是否造成闪烁或割裂

- 结论：**未发现旧封面冒充新歌或长时间挂着旧图**；也没有证据要求改占位/取消时序，因此没有改生产代码。
- 仍存在一个体验事实：没有封面时显示的是深色音符占位，它是可见的；这不是旧图，但与原版的具体封面内容不可直接比较。
- 离屏阶段图不能可靠复现 SwiftUI `.blur`/`.brightness` 的最终屏幕观感，候选阶段图偏锐；真实屏幕上的模糊/亮度与回弹体感仍待用户肉眼验收。
