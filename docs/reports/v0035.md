## 1. AirPods 电量与型号

### 实际取得的只读证据

未使用外部 TCC probe，也未向用户运行中的候选注入代码。只读 Objective-C
runtime 查询实际 selector 返回编码：

- `batteryPercentLeft/Right/Single/Case/Combined`：`C`（unsigned char）
- `colorID`：`C`
- `isConnected`：`B`
- `name`/`addressString`：`@`

证据：`docs/verification/v0035/logs/native-selector-types.log`

**根因证据**：旧 native `connectivityScalar` 使用
`unsigned int(*)(id,SEL)` 调用这些 `unsigned char` selector，ABI 不匹配。
因此不能把旧值当作确定电量；本次未取得当前 AirPods3 的原始字段值，不宣布
某个旧读数已确诊为唯一原因。

### 最小修复

- `NativeBridge.m`：
  - 通过 `method_copyReturnType` 验证返回类型必须精确为 `C`；
  - 使用 `unsigned char` 函数指针读取；
  - 缺失/不支持/非 `C` 返回 `-1`，上层转 nil；
  - `ARConnectedAudioDevices` 的稳定 id 使用规范化地址。
- `AudioDevice.battery`：
  - 有 left/right 时只取左右有效值的最小值；
  - `single` 只有在左右都不可用时才使用；
  - 不再让不适用 `single=0` 覆盖真实耳电量；
  - 0 仍是合法值，不统一过滤，不替换成 100；
  - nil/越界/非可信值不进入环或低电提醒。
- `AudioDevice` 的 AirPods3 model UID `2013 4c` 继续映射既有 AirPods3 资源。

模块现有低电提醒仍为首次基线、阈值边缘触发；未知值不触发红色/低电。
真实 AirPods3 电量环和左右字段仍需用户在候选运行中确认。

## 2. 连接事件与生命周期

新增 `ConnectivitySystemEvents`：

- 仅在 native source + 蓝牙授权 gate + 蓝牙总开关开启时注册；
- `IOBluetoothDevice.registerForConnectNotifications` 监听连接；
- CoreAudio `DefaultOutputDevice` 与 `Devices` 属性监听辅助捕获输出变化；
- 120 ms debounce 合并通知；
- 现有 3 秒 poll 保留为兜底，不提高频率；
- off/stop 注销全部 notification/listener、取消 debounce；
- 连接事件只移除对应规范化设备 id 的 known 状态，不能把输出切换误判为
  任意新蓝牙连接；
- 快速重连可在下一次 3 秒 poll 前触发 refresh，使新连接进入 fresh 路径；
- 原有 one-in-flight、generation、late result 拒绝、首次 baseline、不重播
  到达动画均保留。
- Fake source 不注册系统监听，避免测试触发真实 IOBluetooth/TCC。

## 3. 音乐点击响应

审查 `MediaController.command`、`SystemMediaSource`、`MediaProgressView`、
`WindowCoordinator`：

- `SystemMediaSource.perform` 本身已在独立 command queue 创建进程，不是
  main-thread 同步 I/O；
- 但按钮没有即时 UI 反馈，要等到 adapter get/send 完成后的 snapshot；
- 本次对播放/暂停加入**可回滚的即时图标/playing 状态**：点击立即反馈，
  真实命令仍在后台执行；失败时恢复原状态并显示既有“播放来源已改变”错误；
- command generation 防止旧完成回调回滚新点击；
- 不跳过来源校验、能力 gate、去重或真实命令派发，不伪造成功；
- 未删减动画、未改手势/封面/歌词/进度 seek 语义。

新增 fake slow source 测试：`perform` 延迟 300 ms 时，`command(2)` 在
100 ms 内返回并即时更新 playing，随后真实命令仍执行一次。
