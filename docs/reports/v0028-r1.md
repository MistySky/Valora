## 1. 实际在途与 stop/start

修复前 `stop` 立即清空 `task/isRefreshing`，旧非合作 read 未结束，重启可再启动第二份。

修复后：

- provider 用实际 `inFlight` Task 作为所有权锁；stop 只递增 generation、取消 timer/Task、置 active=false，不清 in-flight latch。
- start 在旧 in-flight 存在时只设置 pending；旧工作真正结束后释放 latch，旧 generation 结果只计入 discarded，不提交，然后启动最新合并请求。
- 普通 stop 后不复活；restart 不永久禁用；最多一个实际在途。
- transport 的 `defer server.stop()` 改为显式 `stopAndWait`：先发 SIGTERM，再覆盖 2 秒 grace；detached waiter 即使 Swift Task 被取消，也等待实际子进程退出/被杀。
- 暂停/隐藏/sleep-wake/退出仍通过 provider/timer/task/status item 清理；没有新增生产定时器。

新增/保留回归：

- 独立 `testStopThenRestartDoesNotOverlapAnUnfinishedRead`（受控未完成 provider）通过，max in-flight 1。
- `testRestartAfterUnfinishedReadRunsLatestOnlyAfterOldCompletes` 通过，旧工作结束后启动最新且仍 max 1。
- 本地 fake child `testCancellationTerminatesFakeChild` 通过，取消后真实 shell 子进程被终止。

## 2. 新鲜缓存/打开节流

- 成功快照在 `freshnessInterval`（默认 45 秒）内，`refreshOnOpen()` 直接展示，不启动新进程/网络请求。
- 失败有 `failureCooldown`（默认 60 秒），开窗不能绕过冷却；过期后允许一次有界刷新。
- 后台定时仍为 180 秒；失败按已有指数退避（上限 900 秒）。打开期间已存在 in-flight 时只合并 pending，不并行。
- 时钟注入的失败冷却测试通过；独立 rapid reopen 测试（10 次）现在请求数不再增加；provider start/in-flight/stop 仍保留单在途断言。

## 3. 严格解析

- `rateLimitsByLimitId` 字段存在但为字符串/数组等错误类型：协议失败，不回落旧 `rateLimits`。
- map 为空：仍权威，不回落。
- map 为 null：按 nullable 语义视为缺失，仅此时允许 legacy fallback。
- map 内 `codex` 桶错误类型：协议失败；无 codex 或 codex=null：明确无全局窗口；其他桶不混入。
- 旧 legacy 字段存在但错误类型：协议失败，不伪造数据。
- `integer` 使用 `-2^63 <= x < 2^63` 的 exclusive 上界，避免 `Double(Int.max)` 舍入后 `Int()` trap；边界 fixture 通过。
- 0/1 数值仍为真数字；只拒绝 `objCType == 'c'` 的 JSON Bool。
- reset `availableCount` 仍权威；credits 缺失/少于总数不假零；到期仍按真实值排序，缺少到期时间如实显示。
- 重复 credit id 用稳定的 `id#2` 等有界后缀区分 ForEach 身份，不丢弃、不合并、不改数量/到期时间；新增测试通过。
