## 1. R1 修复

### 1.1 false → true 初始读取与 stop 生命周期

- `ConnectivityController.start` 现在建立可重新创建的订阅；`stop` 明确设置 `started=false`、移除 subscriptions、取消 timer/query/toast、停止声音并清理状态。
- 开关订阅保留成熟实现的发布时序处理：`@Published` 在 willSet 阶段发出时，先完成 state/timer 处理，仅把**初始读取** `DispatchQueue.main.async` 到属性提交之后。这样 false→true 在 150ms 内读取一次，不等待 3s timer，也不会在 willSet 读到旧 false。
- `refresh()` 增加 `started` 门禁；stop 后直接的 refresh、旧 timer 或已排队设置事件不能重新启动查询。显式 `start()` 可重新建立订阅和新一轮基线。
- `stop` 不清除 `queryInFlight`；正在不合作返回的底层读取仍是**真实单 in-flight**，不会因 stop/start 或关闭/重开而无限并发。旧 source 返回后只释放 in-flight 一次，若已重启且仍启用才发起新一轮；旧 generation 结果严格丢弃。
- `AppDelegate.applicationWillTerminate` 仅在 `modelWasLoaded` 时访问 model，调用 `model.bluetooth?.stop()`，不会为退出而 lazy 初始化新的 AppModel/ConnectivityController 或发起查询。

### 1.2 声音停止

- `LowBatterySoundPlaying` 增加 `stopLowBattery()`；保留默认空实现以兼容既有测试替身。
- `AppKitLowBatterySound` 保留 `NSSound` 实例，设置 `NSSoundDelegate`，播放完成或主动 stop 后释放。
- 低电量总开关关闭、`ConnectivityController.stop`、deinit 以及重新配置启用状态时主动停止当前声音；低电量边沿去重/重新武装逻辑保持。
- QA spy 增加 `stops` 计数；设备 QA 验证关闭和 controller stop 都会停止声音且不会在关闭后再次播放。未实播声音。

## 1.3 权限手形入口

- 手形沿用 `SettingsToggleRow` 的 `hand.raised.slash.fill`、位置/颜色/大小和“需要授权”可访问性状态；**手形仅作为 Image 状态标志，不是 Button、不可点击**。
- 用户最新纠正的开关交互：开关本身不再 `disabled(blocked)`；点击开关时才进入权限意图。共享 `PermissionToggleRouting` 用于三个实际设置行；未授权时不写入开启，只开始一次 pending 意图。
- 设备连接：公开 `CBManager.authorization` 状态；`.authorized` 正常开启，`.notDetermined`/`.denied`/`.restricted`/unknown 显示手但开关可点。`.notDetermined`/unknown 点击开关使用一次现有 IOBluetooth 只读探针；`.denied`/`.restricted` 打开蓝牙隐私设置。**没有0.8s超时判定**；只在真实状态/应用激活时收尾。
- 实时波形：Core Audio process tap 没有可靠的公开预读状态，初始明确 `unknown`；点击开关调用现有 `LiveAudioTap.startAsync`，成功才转为 authorized；失败保持 unknown 并反馈，不冒充拒绝、不硬编码永久封死。已经开启的波形在 unknown 时仍可关闭。
- 登录时启动：`SMAppService.mainApp.status == .requiresApproval` 时手形作状态，点击开关打开 `SMAppService.openSystemSettingsLoginItems()`；不把登录项批准当蓝牙/TCC。
- pending 意图可见为一次开启尝试；成功授权后自动完成本次开启（标志消失、开关实际开启），拒绝/取消/失败保持关闭并清除 pending。连续点击不创建多个请求；用户切回关闭会取消 pending；外部权限变化没有 pending 时不自动开启全部功能。
- 权限关闭时已保存的蓝牙开关会被安全关闭；关闭功能不会撤销系统权限。普通歌词、外观、悬停等无需权限的项目没有手形。

权限映射/API 依据：`docs/research/connectivity-bluetooth-permission.md`、`docs/research/permission-hand-mapping.md`。

### 用户确认的设备范围减项

- 设置只保留功能总开关；外观不再显示 3D/Symbols tile，固定自动选择；显示时长、低电量提醒、阈值、提示音不显示设置项。
- 固定策略：5s、低电量提醒开启、20%、提示音开启；旧隐藏键不覆盖。
- 未迁入 Focus/Lock 允许项、配对/连接/音频切换设备管理、系统电池/日历/锁屏模块。
- 未把现场 current 值冒称原版注册默认；总开关保守默认关闭，外观自动选择，详见 `docs/research/connectivity-defaults-and-source.md`。
- 自动外观：已有识别型号且本地电影资产存在时使用 3D；缺少型号/资产或 Reduce Motion 时使用 `AudioDevice.symbol`（已知型号缺动画用型号符号；已知 AirPods 但型号未知用 `airpods`；其他用 `headphones`）。旧 `connectivityModel` 不得覆盖该策略，外观 tile 已移除。

### 必要的产品/多屏约束

- 连接提示优先于紧凑音乐/歌词/Quick Peek；提示期间不叠字，结束后恢复现有歌词/音乐。`showsCompactLyrics` 与 `visibleSize` 的顺序是用户确认的连接提示优先级，不是新设计。
- 活动屏显示 3D/符号与动画；被动屏只保留静态紧凑音乐，不挂载隐藏连接/展开电影层。
- 资产缺失/Reduce Motion 使用符号回退；3D 资源按原版尺寸/偏移，不改变布局。
- 这些是与已接受的歌词、多屏和连接提示优先级整合的必要边界，不替换成熟设备组件。
