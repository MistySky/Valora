## 1. 根因

V0023 的首次 normalization 会写 `draft.launchAtLogin=false`；旧 `SettingsView` 还有一个泛型
`.onChange(of: draft.value("launchAtLogin"))`，内部直接读取全局 `LoginItem.isEnabled` 并调用
`LoginItem.set(enabled)`。因此注入 `requiresApproval`、真实 SM 状态为 enabled 时，程序性纠正可能注销真实登录项。

“只改 Valora 配置”的声明在旧实现中不成立；不能用“本机测试时登录项恰好关闭”证明安全。

## 2. 修复

### 2.1 删除程序性系统写入口

- 删除 `SettingsView` 的泛型登录项 `onChange`；该 onChange 是唯一在程序性 draft 更新时直接写 ServiceManagement 的路径。
- normalization、权限 refresh、外部状态纠正、首次挂载只写 Valora 自己的 `SettingsDraft`/`RevivalSettings` 偏好，不再调用 `LoginItem`。
- `SettingsView` 不再直接引用 `LoginItem.isEnabled`/`LoginItem.set`；生产系统动作只经 AppDelegate 注入的 `AppPermissions` 回调。

### 2.2 保留显式用户行为

- 显式用户开启：继续走 `beginLoginEnable` → 注入的 `loginRegister` → enabled/requiresApproval 流程；成功后或当前意图完成才 on。
- 显式用户关闭：`loginBinding` 的 cancel 改为 `AppPermissions.disableLoginItem()`。
  - 当前已启用：调用注入的 `loginUnregister`，真实关闭；
  - 当前 pending 且本次注册所有：取消并按原逻辑撤销本次注册；
  - 已有 `requiresApproval` 但非本次拥有：不注销旧注册，只去掉本地意图；
  - 无注册：只清本地。
- `disableLoginItem` 使用 generation token；旧 unregister 回调不能覆盖新的登录意图/状态。
- 不删除已有所有权、旧 callback 拒绝、pending 不重复请求、authorized-on 保持等逻辑。

### 2.3 初始/外部状态

- 首次 normalization：只纠正 Valora 偏好，不发起任何系统动作。
- 外部 grant/status 变化且无开启意图：不自动注册、不自动注销、不自动重启功能。
- 授权 already-on + 已存本地 on：保留。
- `ConnectivityController` 等授权 gate 未改。
