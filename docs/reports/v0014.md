## 1. 方法与环境

- 新增 QA 入口 `--audit-fluidity <dir>`，生产默认不启用；使用 fake `AppModel`、`AuditLyricsProvider`、两个注入 `DisplayDescriptor`，不启动 `MediaController`、音频 tap、真实网络或系统写操作。
- fake 歌词包含真实 word timing 的长句、短句、行-only 长句；播放阶段覆盖短句→长句→短句，另含展开/音量行、恢复/双向 seek、暂停/隐藏/关闭歌词/被动屏。
- 资源采样：进程内 `getrusage(RUSAGE_SELF)` 获取 CPU，`mach_task_basic_info.resident_size` 获取 RSS；约 1s 一次。CPU 为进程级、包含测量辅助代码。
- 动画观测：`CompactLyricsView` 的 30Hz `TimelineView` body 回调计数；`NSWindow.displayLink` 的系统回调计数。**两者都不是合成器实际渲染帧数，也不是 60fps 或人眼流畅度证明。**
- 时段：baseline 10s、compact play 30s、expanded 5s、resume 5s、paused-before-idle 1s、paused-through-idle 30s、line-only 8s、hidden 30s、lyrics-off 20s、passive 20s，合计 159s。
- 环境：macOS 27.0.1 (26A434)，10 logical cores，32GB；采样原始值见 `audit/audit.json` 的 `environment`。

## 2. 实测发现与修复

### 已修复：被动屏后台挂载展开歌词 Timeline

- 审计初版在 expanded 阶段观察到约 **300 次 Timeline body 回调 / 5s（≈60Hz）**，而单个 30Hz 歌词视图应约 150 次/5s；对应 CPU 也明显高于 compact。
- 定位：`NotchView` 的 expanded content 只判断 `model.presentation.retainsExpandedContent`，没有排除 `compactOnly`。被动屏虽然不显示动态内容，却仍构造了不可见的展开 `CompactLyricsView`，其 Timeline 持续刷新。
- 修复：`Sources/Valora/NotchView.swift:111` 改为
  `if !compactOnly, model.presentation.retainsExpandedContent { ... }`。
  被动屏仍保留原 compact 外观、交互和主动屏归属，不显示/不构造展开层。
- 修复后最终原始数据：expanded 阶段 **150 次 / 5.0s（约30Hz）、roleTicks 仅 `expanded`**；同轮 CPU 从迭代中约 11.9% 降到约 7.9%（温度/调度有波动，只作为方向性证据；最终 raw 见 `audit.json`）。修复前的临时迭代 JSON 已被最终运行覆盖，未作为正式原始文件保留。

### 未发现问题的场景

- compact 播放 30.04s：Timeline 901 次，短/长句切换 3 次，真实 word index 变化 6 次；lyrics request 0（初始 1 次后不再请求）。
- expanded + volume：150 次/5s，只有 `expanded` role；音量行关闭/恢复歌词行保持。
- 双向 seek：前向/后向均落到正确行；恢复后 5s 内 151 次 Timeline 回调。
- 暂停：暂停前 1.06s 内 Timeline 0 次，歌词行保持；成熟 3s 暂停 idle 后，30s 内 Timeline 仍为 0 次，界面按既有逻辑隐藏。**不把暂停 idle 的预期隐藏当成动画仍在刷新。**
- 隐藏：30s 内 Timeline 0 次，panel 不可见，display link 也停止。
- 关闭歌词：20s 内 Timeline 0 次；窗口仍可见所以 display link 回调仍约 60Hz，未宣称进程绝对零 CPU。
- 被动屏：主动 external 屏 600 次/20s；被动 built-in 屏 `passiveTicks=0`，不存在重复歌词 Timeline。
- 快速 A→B→A：provider calls=3，cancellations=2，completions=1，inFlight=0；最终 A ready，`verificationTaskIsActive=false`。

## 4. 代码改动

- `NotchView.swift`：被动屏不再构造不可见的 expanded content；这是唯一行为相关修复，视觉/交互保持。
- `CompactLyricsView.swift`：增加默认关闭的 `LyricsFrameProbe` 计数 seam 和 `auditRole` 标签；生产正常模式不启用 probe。
- `LyricsController.swift`：增加 `taskRunning` QA 状态和取消清理；使“无悬挂请求任务”可被审计，不改变请求/预算/缓存语义。
- `AppRuntimeDefaults.swift` / `AppDelegate.swift`：增加仅 QA 的 `--audit-fluidity` 入口，不进入生产启动流程。
- `FluidityAudit.swift`：新增可复用隔离测量器；无新依赖、无后台常驻进程。
