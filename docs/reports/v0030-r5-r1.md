## 1. 根因与修复

R5 的 `start()` 只为启动时已启用的模块注册 observation。启用状态下从 off→on，
`setSystemMonitorVisible(true)` / `setCodexVisible(true)` 没有重新安装 observation，
因此 provider 的后续 snapshot 能更新自身，却无法把共享 status item 的 tooltip/图同步。

修复：

- 每个模块有独立 observation epoch：
  - `monitorObservationEpoch`
  - `codexObservationEpoch`
- `setSystemMonitorVisible(true)` 启动后调用 `observeMonitor()`。
- `setCodexVisible(true)` 启动后调用 `observeCodex()`。
- 关闭一个模块只递增它自己的 epoch、清除自己的 active 观察；另一模块继续更新。
- `stop()`/`start()` 递增两个 epoch；旧 session 的晚到 observation callback 因 epoch 不匹配直接返回，不覆盖新 session 的观察标志。
- 共享图/tooltip/accessibility 的更新仍走 `updateCombinedImage()`，不是只画首次图，也不依赖点击。
- 共享 status item 重建时清空 `lastCombinedKey`，避免旧图像 key 让新项首次不绘制。
- 双方关闭时 provider 与共享 status item 都不存在；不重复 provider/observer/timer。
- 生产 `samplingEnabled` 仍为 true；QA 的 `startSampling:false` 不会被后续 enable 意外开启 monitor 采样。
