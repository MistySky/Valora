## 阻断问题及确定的返修方向

### 1. 持续播放不自行切句（高优先级，已复现）

`NativeLyricsRow.swift:131` 的 `render` 只推进已有行内的词，不根据插值时间重新选择歌词行。`clockTick` 直接调用它；连续更新模式还会跳过边界定时器。

独立用例在第一句起点传一次快照，随后推进到第二句起点后 0.1 秒，仍显示第一句，且仍判定需要连续刷新。若宿主每秒更新一次锚，将依赖宿主更新才换句，可能产生接近一个采样周期的延迟。

返修：以同一个插值时间先选择行，再计算该行填充/滚动；跨行时准备一次静态数据并重新选择连续时钟或下一边界唤醒。不得依赖宿主提高刷新频率掩盖缺陷。增加真实时钟路径的隔离用例，覆盖逐字行→短静态行、长 LRC→短行、静态行→逐字行及暂停恢复。

### 2. 当前行不变时沿用过期行尾（已复现）

`apply` 只有行或身份改变才调用 `prepare`，而 `lineEnd` 只在 `prepare` 中重算。新时间轴把下一句从 20 秒改到 10 秒，原型仍保留 20；末行时长从 100 秒更新到 120 秒，仍保留 100。这会使长句滚动速度或位置错误。

返修：把行尾失效与文字重建分开，真实后继和时长更新须及时生效；可复用已修正的生产缓存。纯行尾变化不得重播换句动画。

### 3. 绘制属性更新未重建文字（字距已复现）

`apply` 在字距改变时仅重新布局，原 attributed string 与测量宽度不变。测试从 kern 0 改为 2，宽度完全未变。代码检查还显示强调色更新没有独立失效路径，显示倍率仅在构建文字时读取。

返修：明确文字内容/绘制属性、行尾、几何、显示倍率各自的失效条件。颜色只更新必要绘制数据；字距影响文字和尺寸；屏幕倍率变化须更新 contentsScale；这些变化不得触发换句动画。以原版绘制口径为基线，不擅自统一字距改变现有体感。

### 4. 换句动画不等价（代码检查，尚未逐帧验证）

`animateSwitch` 只有新行位移动画，缺少生产 `.combined(with: .opacity)` 对应的淡入。旧行移出动画结束后未设置模型终态，却延后 50ms 才移除，有闪回风险。旧清理回调无代次校验，会移除新一轮动画；清理还使用 `snapshot.sampledAt` 重绘，可将当前高亮短暂退回锚点。

返修：保留现有 0.2s easeInOut、±26pt 和双向透明度；设置正确模型终态；清理仅处理本轮出栈层，不清除后续换句动画；重绘使用当前时间。补连续快速换句和动画完成瞬间的隔离验证。

## 视觉与性能结论

- OC 的 2x 像素报告本身已记录明显差异，尤其长句；本轮未重跑像素探针，也未独立确认其归因。仅数值公式相等不能证明排版、抗锯齿和过渡体感相等。
- 保持现有 SwiftUI 绘制与测量口径，先修原型，再做 1x/2x、长短句、中文/emoji、过渡帧对照。不能用调整现有生产字距来迁就原型。
- 连续 30 帧没有文字重建只是局部工作量证据，不是 CPU 降幅。原型尚未接入，不能期待当前运行版因此降低 CPU，也不能宣布歌词高占用已解决。
- 修复上述缺陷并通过体验对照后，才具备开展可比播放场景 CPU 验证的条件。当前保留 Debug 隔离原型，不交付替换版。
