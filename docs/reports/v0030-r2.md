## 1. Automatic/queued download starts obey feature-off

The R1 service barrier only tracked `resume`. V0030 now closes the deferred
automatic-start path as well:

- `DownloadManager` has an explicit action gate independent of list ownership:
  - `suspendActions()`
  - `resumeActions()`

  start-all-waiting all refuse to begin while the gate is suspended.
- `DownloadEngineService.activate()` calls `resumeActions()`.
- `pauseAllAndSave()` calls `suspendActions()` before generation invalidation,
  action cancellation, manager pause and save.

  `actionTasks`; `enqueue/start/resume/retry/resolve` are rejected after off.
- Default automatic downloads remain enabled during normal operation; this did

## 2. Holiday EventKit transport and queued Task boundary

- `HolidayEventTransport` is injectable:
  - `EventKitHolidayTransport` owns the only real `EKEventStore`, created
    lazily only after started + panel visible + authorization gate.
  - `FixtureHolidayTransport` supplies records/calendars and exposes
    `calendarReadCount/eventReadCount`; it never creates EKEventStore.
- `HolidayProvider` default is non-reading (`transportFactory = nil`); production
  `AppDelegate` explicitly injects `EventKitHolidayTransport`.
- `CalmonCalendarModel` default/preview/test provider is `nonReading`; production
  passes the real provider explicitly.
- No EKEventStore is created in `HolidayProvider.init`.
- StoreChanged observer is installed only for a real transport, and removed on
  hide/stop; callback rechecks started, panel, authorization and fixture mode.
- `loadEvents` rechecks started/panel/authorization/generation at the actual
  transport execution boundary. A Task queued before hide/stop is rejected
  before it calls transport.
- The in-flight latch is released on that pre-transport rejection. A newer
  pending range starts only if the panel is still active; otherwise a later
  open starts a fresh read.
- Existing in-flight results remain protected by generation; late result after
  hide/stop is discarded.
- Existing holiday mapping, marker/badge, normal+arrangement dedup and
  same-name personal-event preservation remain intact.

Directed tests include:

- inactive/hidden provider: transport factory count 0;
- unauthorized provider: transport factory count 0;
- fixture transport counters: calendar/event calls observable, no real store;
- hide immediately after `ensureEvents` before queued Task runs: transport
  eventReadCount 0, then reopen can make one fresh read;
- rapid month ranges while one read is gated: only latest pending range starts
  after old result is discarded;
- late result after hide does not repopulate holiday data;
- gate off clears holiday badge/detail and does not start another event read;
- prior holiday fixture/native mapping remains.
