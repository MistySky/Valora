## 1. 隐藏再显示状态项立即恢复

**复现**：`setCalendarVisible(false)` 移除已有的 `NSStatusItem`，再显示时创建新按钮；`lastCalendarText` 仍保存旧文本，`updateCalendarImage` 因相同文本提前返回。新按钮因此没有 image/tooltip/accessibility date，直到下一次日期变化。

**最小修复**：

- `MenuBarModuleController.setCalendarVisible(false)` 移除日历 status item 后清空 `lastCalendarText`；显示时 `calendar.handleWake()` 后立即 `updateCalendarImage()`。
- 同步清空 `lastMonitorKey` 于监控隐藏路径；恢复时立即重绘 CPU/MEM image，不依赖下一次 3s 采样。
- 不改变 status item 创建顺序、日期/MEM 字体、布局或点击路由。

**回归**：`IndependentMenuBarMigrationTests` 两项均通过：
- `testCalendarHideThenShowRestoresNativeDateImageImmediately`
- `testMonitorHideThenShowRestoresNativeMetricImageImmediately`

## 2. 日历授权发布后的自动读取

**复现**：`AppDelegate` 原 `permissions.$calendar.sink` 在 `@Published.willSet` 内同步调用 `model.refreshEvents()`；`readGate` 读取 `permissions.calendar` 的旧值（denied），即使面板已打开且授权随后变为 fullAccess，provider 读取次数仍为 0，需再点一次。

**最小修复：共享生产接线**

新增 `Sources/Valora/CalendarAuthorizationRefresh.swift`：

- 生产 `AppDelegate` 不再直接绑定原始 sink，改用 `CalendarAuthorizationRefresh.subscribe(appPermissions, onRefresh:)`。
- 该共享入口只把刷新延后一个主队列回合，让 `@Published` 完成提交，再由现有 `CalmonCalendarModel.refreshEvents()` 重新检查 `started / panelVisible / calendarModuleVisible / enableCalendar / fullAccess`。
- 它不自行请求授权、不绕过模型 gate、不新增隐式读取。

独立回归 `IndependentMenuBarMigrationTests.testPublishedCalendarAuthorizationRefreshStartsReadAfterGrant` 现在调用同一个共享生产入口，不再复制私有新逻辑。

新增边界回归：

- `testCalendarAuthorizationRevokeClearsAndStopsWithoutRevivingQueuedGrant`：
  - denied → fullAccess 已开面板自动读取 1 次；
  - 再 denied 清空事件、eventState 回 `notAvailable`，不产生第二次 provider 读取；
  - 停止后再次排队 grant，不复活面板、不读取。
- 原有 `IndependentCalendarLifecycleTests` 的 stop/隐藏不读、快速切日单在途、跨月跟随今天、调度前失权、原生日期条首日更新语义保留。
