## 2. 状态环

`DownloadRingIcon` 是一个 18×18 template `NSImage`：

- 已知大小：按各活动任务 `downloadedBytes / totalBytes` 的实际合并比例画环；不会把多个任务伪造成 100%。
- 未知大小/正在合并：只有一个有界模型 timer（0.25s）驱动环相位，不建立每帧 timer，也不建立每行 timer。
- 暂停：静态环+箭头，不推进动画。
- 空闲：静态环，timer 停止。
- 失败（仅失败任务时）：静态警告环。
- 状态环不缓存无限图片：每次状态变化只生成当前图片；关闭/暂停/空闲后 timer 停止。

## 4. 新建/冲突/删除

- `DownloadNewView` 保留 Convoy 的 URL 输入、卡片、保存位置、取消/提交结构；仅支持 HTTP(S)，没有 YouTube/helper/剪贴板静默导入。
- 新建提交通过 `DownloadMenuModel.enqueue` → 薄 `DownloadEngineService`；重名冲突由 service 转为 UI-safe `DownloadServiceError.conflict`，并在模型刷新后显示冲突 sheet。
- `DownloadConflictSheet` 保留四个原生决定：保留现有、重新下载、另存为建议名称、跳过。
- `DownloadDeleteConfirmation` 保留：
  - 默认只删记录，完成文件保留；
  - 显式勾选才将完成文件移到 Trash；
  - 未完成下载丢弃 partial 进度；
  - 取消不修改任务或文件；
  - 零数据/文件已不存在走 trivial 旁路。
- QA 使用 `FakeDownloadService` 的操作 spy；没有真实文件/Trash 操作。

## 5. 生命周期与隔离

- `DownloadMenuBarController` 只持有一个 `DownloadMenuModel` 和一个 `DownloadServicing`；打开/关闭 popover 不创建 manager，不停止下载，不清恢复数据。
- 生产 `AppDelegate` 在正常启动时构造一个 `DownloadEngineService(environment: ValoraDownloadEnvironment.production())`；QA/验证模式使用 fake，不构造生产 manager。
- `stop()` 关闭 popover、移除状态项并调用一次 `service.shutdown()`（只 `saveBeforeTermination`，不取消任务）。
- 应用启动时 manager 只读取自己的 Valora 记录；不自动恢复网络请求，恢复任务保持 paused。
- 存储不可用通过 `downloadListUnavailableReason`/模型状态显示，新增下载被 service 明确拒绝。
- 关闭 popover 后 active 任务继续；空闲/暂停时模型 timer 停止。
