## 1. 根因与签名修复

Codex 只读 TCC 证据显示：

```text
kTCCServiceCalendar requires entitlement
com.apple.security.personal-information.calendars
```

实际 `dist/Valora.app` 为 ad-hoc + runtime，但旧 `scripts/package.py` 只有
`--options runtime`，没有 entitlments。

新增：

- `Resources/Valora.entitlements`：仅
  `<key>com.apple.security.personal-information.calendars</key><true/>`；
- `scripts/package.py` 最终 app 签名：
  `codesign --force --sign - --options runtime --entitlements Resources/Valora.entitlements Valora.app`；
- 签名后从**实际 app**读取 `codesign -d --entitlements :-` 并解析，确认键为 true；否则构建失败。
- 保留 `NSCalendarsFullAccessUsageDescription`；未开启 sandbox，未添加联系人/提醒事项/摄像头等权限。

最终签名证据：

- entitlements 导出：`docs/verification/v0016-r2/entitlements-export.txt`
- `codesign -d --verbose=2`：`flags=0x10002(adhoc,runtime)`、`Runtime Version=27.0.0`
- `dist/build-verification.json`：`calendars_entitlement_present_in_signed_app=true`、`codesign_runtime_flag_present=true`。
- `codesign --verify --deep --strict` 通过。

## 2. 请求失败诊断

- `CalendarAuthorizationProviding` 增加 failure-aware 路径的默认实现，兼容既有测试替身；`EventKitCalendarAuthorization` 保留 EventKit completion 的 error。
- `CalendarAuthorizationFailure` 只保存 `domain`/`code`，不记录日程或隐私内容。
- `AppPermissions` 区分：
  - 真正 `fullAccess` 才完成开启意图；
  - `.writeOnly` 仍不可读；
  - 请求 error 保留为“请求失败（domain code）”并保持功能关闭，不伪造成 denied；
  - 取消/失败不完成 pending；generation 防止迟到旧 callback 完成新 intent。
- 正常成功、取消、pending、手形 Image/开关唯一入口均保持 R2/R3 已接受行为。
