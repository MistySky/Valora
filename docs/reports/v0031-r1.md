## 1. `onDeterminingFilename` 收尾

`Resources/ChromeExtension/background.js` 现在：

- 每个分支通过同一个原子 `settle()` 恰好调用一次 `suggest()`：
  - 非 HTTP(S)、本扩展来源、非 in-progress、过期项；
  - Valora 状态不可用/功能关闭/host 缺失；
  - 下载请求未被接受；
  - 接受后 Chrome cancel 成功、失败、异常、超时；
  - 外层异常。
- 成功路径也在 cancel callback/超时后调用 `suggest()`，不再漏 Chrome 要求的唯一回调。
- 只有 `ok:true` **且 `accepted:true`**、`protocolVersion=1`、`app=Valora`
  同时成立才调用 Chrome `cancel`；仅 `ok:true` 的未确认响应不会转移下载。
- `cancel` callback 读取 `chrome.runtime.lastError`：失败时不 `erase`，
  保留 Chrome 下载记录并提示可从 Chrome 恢复；成功才 erase。
- `nativeRequest` 有 8 秒生产 deadline；Node fixture 仅通过
  `globalThis.__valoraNativeDeadlineMs` 缩短测试等待。late callback 被一次
  性 latch 丢弃，超时后不会再次 cancel/erase/提交。
- host 不回调、状态超时、下载超时、功能关闭、host missing 均回到 Chrome，
  不吞下载。

## 2. Native host 入口

`Sources/ValoraNativeHost/main.swift`：

- 在 `status/ping/download/launchApp/getDownloads/pause/resume/cancel`
  全部分派之前：
  - 校验 `CommandLine.arguments` 的 Chrome 调用 origin，必须精确为
    `chrome-extension://micfejmbldlgjepdfadhnoalmcbnpllb/`；
  - 校验 `protocolVersion` 存在、为整数且精确为 `1`；缺失/999/字符串等
    直接返回 `ok:false`，不会重写成 1。
- 无效版本/错误 origin/缺失 origin 不会进入 App 身份或 socket 操作。
- 正确版本且 app bridge 可用时返回 `bridgeEnabled:true`；
  app 进程在但下载/桥接关闭时返回 `appRunning:true, bridgeEnabled:false`；
  app 未运行时返回 `appRunning:false, bridgeEnabled:false`，供 popup 区分。
- App 侧仍保留 `validateEnvelope` 的版本/App/host/bundle 身份检查与
  socket peer signature 校验，未放宽 peer。

## 3. popup 状态机

`Resources/ChromeExtension/popup.js`：

- `open` 初始 hidden，但 render 现在会明确设置 visible：
  - 已连接：hidden，不重复打开；
  - host 未注册：hidden，显示真实设置引导；
  - App 未运行：显示“打开 Valora”；
  - App 运行但下载/桥接关闭：明确显示该状态，并显示“打开 Valora”；
  - 版本不匹配/无响应：显示可操作状态，不伪装已连接。
- `open` 点击有 disabled 防重复，并在打开后延迟刷新状态。
- popup 有 5 秒 native deadline，host 不回调不会永久“正在检查”。
