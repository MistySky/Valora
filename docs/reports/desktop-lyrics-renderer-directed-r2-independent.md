2026-11-07。R2 指定的三项失败已修复，原型仍不能接入生产。

复测命令沿用 R1 独立报告同组过滤器。新增 3 个真实 RunLoop 回归后，共 52 项：49 通过、2 失败、1 跳过。日志 `/private/tmp/valora-lyrics-r2-independent-final.log`。之前所有 7 个独立用例均通过，新增“真实 Timer 在无宿主更新时换句”通过。

## 尚存同步问题（已复现）

1. `apply` 使用 `snapshot.sampledAt` 作为显示时刻。真实 Timer 从甲切到乙后，宿主以相同播放锚重绘（并非 seek），再次 apply 就回到甲。预览新加的 onLineChange → SwiftUI @State → updateNSView 链路正可能重送这个锚，造成回跳。应当用当前显示时刻插值，采样时间只作为锚参与计算；不能靠只忽略相同快照掩盖旧采样首次到达的问题。
2. `setActive(true)` 只同步时钟，没有先追上当前进度。静态甲在隐藏期间跨过乙的边界后恢复，仍停在甲；计时器因下一边界已经过去返回 nil。应在 false→true 时先按当前时刻刷新选行和显示，再调度。重复 true 应幂等，避免无意义强制重建。

新增失败：`testReapplyingSameAnchorAfterAutonomousSwitchDoesNotRewind`、`testReactivatingStaticLineCatchesUpAcrossMissedBoundary`。两例使用当前真实时间锚、各等待约 0.15 秒，不使用 1970 锚、不启动窗口或真实播放。

时间语义修复须覆盖首次收到延迟锚、真正前后 seek、暂停/恢复、宿主无障碍回调重入；测试可用明确注入当前时钟来保持确定性，不能让生产默认显示时刻取旧采样时间。

## 视觉核验

独立查看 `/private/tmp/valora-row-r2/` 的四张 2x PNG（长句滚动、逐字填充各有 shipped/native）。原型长句的笔画覆盖和粗细有可见差别，整体显得更细；这不是仅凭统计推断。逐字图也存在字形/边缘差异。

同一名义字体与数值公式不能证明渲染一致；最佳整数位移为 0 也不能排除小数坐标和字形度量差异。R2 所称“来自抗锯齿”的具体归因仍未被完全定位。保持生产外观，不调整生产字距或字体来迁就原型。不能以本轮修好调度即宣称满足体验要求。
